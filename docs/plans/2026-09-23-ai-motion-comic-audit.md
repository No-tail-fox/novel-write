# AI 漫剧制作方案与页面审查（2026-09-23）

## 首轮发现

1. 现有实现已有源文导入、规则拆分、逐集结构化、分幕分场、资产与 DirectorDesk 阶段；此前的八阶段重构基础仍在。
2. `splitMotionComicSourceEpisodes` 的 `chapter` 与 `ai-logic` 当前共享章节/自然段规则，`ai-logic` 只是在类型层存在，真正的语义拆分由后续逐集规划承担；页面需要把两者的职责说明清楚。
3. 长篇源文不应被固定 100 集上限截断；现在源文分集、项目分集和 AI 分集边界均按原文完整性校验，不再使用 100 集硬限制。仍保留总原文 1,000,000 字、单集 30,000 字及单场/单镜头数量保护。
4. 分集页与分幕页都使用自己的 20 集切片，分集页还限制“按顺序逐集解锁”；这会让长篇小说看起来不全，需要确认总数、切片和当前选集三者是否同步。
5. 漫剧 schema 只接受标准字段，规划层已有 normalize 兼容 `name/environmentPrompt/lightingPrompt`、缺失造型、非法 beat 字段和重复名称；还需验证 normalize 是否覆盖缺失原文引用和模型未按预期返回根节点的情况。
6. 当前 `normalizeMotionComicScriptRaw` 对缺失 `sourceUnitIds` 回填为 `u-1`，而确定性原文单元使用 `S1`、`S2`……；后续 `validateMotionComicScriptDraft` 会把它判为不存在并阻断，属于修复链自身的契约断裂。
7. 分幕面板已按“集 → 幕 → 场 → 镜头数”展示，但场卡当前直接读取 `scene.script`，而 `MotionComicDramaticScene` 的持久化类型没有 `script` 字段；需要以现有 `episode.script` 或规划 evidence/beat 投影替代，避免页面信息和数据模型脱节。
8. 漫剧 CSS 已设置工作台、分集列表和详情区滚动，但部分内容仍使用内联高度/overflow，且 `padding-bottom: 96px` 只是安全留白，不能替代真正的底部操作区滚动验收。

- 点击未结构化分集不再向持久化 episodes 追加空集；只切换临时预览。分幕关联由集数相等改为 sourceEpisodeId/原文证据。
- Electron QA 进一步发现导入原稿仍调用演示 starter，自动生成虚构人物和三场示例；现改为空的首集占位，确认规划后才创建资产/分镜。前后集顺序检查恢复。
- 长篇章节/集数不再因固定数量上限报错；仍对单段超过 30,000 字显式报错，创建页通过已有反馈组件呈现，避免未处理异常或静默丢失尾部。
- 暂时移除没有 AI 实现的“AI 逻辑拆分”入口，保留真实章节/字数预拆分，并说明逐集 AI 结构化发生的位置。真正全书 AI 语义分集仍是后续工作。
- 分集页不再将场数当作幕数；“查看分幕分场”现在会真正跳转到对应集。只读原文可以选择/复制，不再以禁用输入降低文字对比度。
- DirectorDesk 的父级 stageLabel 变化原来没有同步本地 activeStage/inspectorTab，视频准备度又仅对 VOX 渲染，导致顶部进入视频而右侧停在生图。现仅对漫剧生产阶段同步工具、按阶段显示关键帧/视频按钮、配音页定位字幕、导出页定位审片；隐藏重复流程导航并调整其网格行。VOX 的既有分支保留。
- 未结构化集预览期间，后续资产/分镜/视频/配音/导出阶段禁用，避免误进入另一集的制作内容。
- AI 全书分集已接入现有创建流程：模型只返回连续原文单元边界、标题、拆分依据和上下集承接，服务端从原文确定性重建正文；预览确认前不写入项目，确认后保存策略、模型、边界版本和来源范围。
- 剧本规划每场已强制返回 `actIndex`、`actTitle`、`actBoundaryReason`；确定性校验禁止幕编号跳号、回退和空幕，要求同幕标题一致。提示词禁止为了凑三幕平均分组，并要求边界依据引用具体剧情变化。
- `applyMotionComicPlan` 已直接使用 AI 幕归属，新结果显示“AI 规划”；旧项目缺少来源时显示“规则推断”，人工改幕边界、标题或依据后显示“人工调整”。
- 分幕审核页沿用现有“集 → 幕 → 场”结构，新增幕标题编辑、“从本场开始新一幕”和逐场边界依据；人工调整自动连续重编号。
- 规划弹窗从 Fluent 默认 600px 单列改为 StoryDream 现有的索引/详情工作区，六项摘要、分场索引、镜头列表和幕依据分层呈现；镜头详情独立滚动，底部操作不随内容移出视口。

## 仍需明确的制作方案

1. 导入并保留完整原文 → 规则预拆分并人工确认范围 → 逐集 AI 剧本/资产/节拍规划 → 分镜预览与覆盖校验 → 确认写入 → 资产参考图 → 分镜图 → 远程视频 → 配音/字幕 → 审片导出。
2. 分幕已由规划模型显式返回幕编号、标题和转折依据，服务端验证连续归属后写入；旧项目仍保留规则推断，人工可在同一页面调整边界和标题。
3. 真正 AI 全书分集需要独立规划步骤，输出连续原文范围与拆分依据，不让模型重写/裁剪原文。校验每段恰好覆盖一次、顺序连续、章界与目标时长约束；用户确认后持久化拆分规则与来源范围。
4. 首次规划仍是剧本与分镜共享一次自动修复；显式从 checkpoint 重试分镜时允许新的分镜修复请求，会增加模型用量，需在真实 API 验收时核对成本提示。
5. 本轮不调用付费生成接口；真实模型遵守率和实际远程视频成片质量不能从离线 QA 推断。

## 后续实现顺序（基于当前模型，避免重新造一套工作台）

1. **已完成：AI 分集契约**。保留章节/字数规则，AI 只输出连续原文边界和依据，服务端校验不重叠、不遗漏、不倒序并确定性重建正文；确认后保存策略、范围和版本。
2. **已完成：真实幕边界**。规划 scene 输出幕编号、标题和转折依据，服务端校验连续归属并直接写入；旧项目规则推断和人工调整均有明确来源标识。
3. **已完成：规划可解释与恢复**。剧本校验通过后写入按项目/输入/模型绑定的 7 天本地 checkpoint；分镜失败只重试分镜或明确重新规划。原始响应与归一化结果逐项对照，数组删减也逐项列出；补齐项需用户审核后才允许写入，审核记录随集保存。缺失剧情文本、对白角色与场景归属不再猜造。恢复后分镜修复可额外发起模型请求，并非免费或无限重试。
4. **输入完整性与系列设定**：人工编辑分集正文后缺少与原文范围的一致性证明；应通过不可变来源范围解决。当前字数拆分优先自然段，超长单段需补分段；后续可在句末安全拆分。新项目默认系列类型/世界规则还带模板色彩，应让源文分析建议并由用户确认。
5. **长篇与真实制作验收**：补充 20/100/146 集以上跨区间滚动和重新打开保持当前选集、长对白超视频模型时长的拆镜处理，以及真实服务错误/取消/恢复和整集审片导出的验收。保留现有素材版本、输入指纹、队列和失效处理。
