## 一、这次报错是什么意思

诊断号 d4d37a9c-ebc3-4759-aaad-c600de7de8b3 的提示列出了第 2 场的第 6、10、13、15、42、43、44、45 条剧情节拍（程序索引从 0 开始）。这些节拍声明为 dialogue，但缺少 characterKey。错误文本最多展示 8 条，因此不能据此断定总共只有 8 条。

这不是简单的前端错误，也不能只归因于提示词。尚未取得该诊断的原始模型回包，无法判断每一句的真实说话人。代码核查发现一个确定缺口：normalizeMotionComicScriptRaw 会根据 speaker/character 判定 dialogue，却只保留 characterKey，丢弃了可能有用的姓名信息。于是模型即使给出了 speaker，也可能被本地处理成无角色对白。

当前已有：原文句段编号、剧本/分镜两阶段、实体和覆盖校验、一次修复预算、有效剧本 checkpoint、分镜失败后恢复、应用前的调整审核。不是完全没有归一化或修复，而是角色归一化不完整、修复粒度过大。只加“严格遵守”不能解决这些边界问题。

## 三、建议的完整产品流程

原文导入 → 分集规则选择 → 分集预览确认 → 系列实体清单 → 当前集分幕/分场/节拍 → 对白绑定与校验 → 当前集剧本确认 → 分镜 → 资产定妆/首帧 → 视频和逐句配音 → 实测时长/字幕/合成 → 质检与导出。

| 步骤 | 用户看到什么 | 通过条件与失败处理 |
| --- | --- | --- |
| 导入 | 原文、小说/剧本类型、来源范围 | 原文不覆盖；句段 ID 可追溯 |
| 分集 | 规则拆分：章节/长度；AI 拆分：事件/逻辑边界；每集来源范围与拆分依据 | 不丢章节、不倒序、不重复；集数可扩展，但单次请求仍需有安全大小限制，超大项目分批处理 |
| 系列实体 | 人物名、别名、身份、造型、场景、道具 | 身份跨集复用；只创建定义，不在此时调用生图 |
| 当前集剧本 | 集 → 幕 → 场 → 动作/对白/旁白；每条关联原文 | 幕归属于本集，不为了固定三幕重排剧情 |
| 对白审核 | 台词、说话人、语气、原文证据 | 精确且唯一姓名/别名可映射；歧义、未知或无效角色不能硬绑定 |
| 结构校验 | 按场显示问题，而非只显示 JSON 路径 | 结构合法、引用存在、原文覆盖与顺序一致；编号覆盖不等于文学语义忠实，仍需人工审核 |
| 局部修复 | 失败范围、修复前后差异 | 只改目标字段；有界次数；修复失败不调用下游、不写入正式项目 |
| 分镜 | 镜头、对应节拍、画面/运动描述、预计时长 | 每个节拍恰好归属一个镜头，不漏拍/重复/倒序；长对白需要延时或拆分，不加速硬塞 |
| 定妆/首帧 | 已确认角色造型、场景和道具的参考版本 | 参考资产稳定，修改后标记下游需更新 |
| 视频/配音 | 单镜头任务与逐句音频任务 | 提交与续查分开，保存任务号；异常不盲目重复付费提交 |
| 合成/质检 | 实测音频时长、字幕、时间线和导出 | 用实际音频重新对齐，不把字符估时当最终成片时长 |

### 对白分类规则

- dialogue：某个明确角色说出的台词，必须绑定本集角色表中的合法 key。
- narration：叙述者旁白，通常不绑定角色。
- 兼容当前软件：已有 narration 也表示角色内心独白/画外音，可能带合法 characterKey；本轮不能粗暴删除它，否则会改变配音身份。后续可增加 delivery（spoken / inner / voiceover）来分离演绎方式与说话人身份，并做持久化迁移。
- action：可见动作，不应进入 TTS；可绑定动作主体。
- “说话人未知”不是“旁白”。不能通过将所有失败对白改为 narration 绕过校验。

## 四、本轮已落地

1. 对 speakerName / speaker / character 的显式名称和别名做唯一匹配，转为 characterKey；歧义和冲突不猜测，不修改原始对象。已有非法 key 保留到校验层，不能用另一个姓名静默替换。
2. 增加 DIALOGUE_SPEAKER_MISSING / CHARACTER_REFERENCE_INVALID 机器可读错误码。
3. 当错误全部属于说话人问题时，不再要求模型返回整集 JSON，而是只返回指定 beatKey 的 kind / characterKey 补丁。模型收到原文证据、相邻节拍和角色表；补丁禁止修改 text、sourceUnitIds 或其他剧情字段。
4. 拒绝多余、重复、缺失、越界和携带额外字段的补丁；应用后再次完整校验；仍有问题不进入分镜，也不保存有效 checkpoint。
5. 保持原有单次修复预算，不增加后台无限重试或隐式付费调用。其他结构问题仍沿用原完整结构修复路径，未声称全链路均已局部化。
6. 将角色补齐和类型变化记入现有 adjustments；通过后仍需在当前规划预览审核确认才能写入。
7. 改进纯角色类错误：显示问题数量和人类可读的“第几场第几条”，提示在原文标注角色与旁白，不再只重复底层校验文本。
8. 加强初次剧本提示词中的角色 key 约束、示例和“未知说话人不能直接当旁白”规则。
9. 对“脚本结构已成形但对白绑定失败”的情况保存 7 天草稿、问题路径、诊断号关联错误和本地调整记录；同项目同输入再次打开时不重复调用模型。
10. 在现有规划 Dialog 内增加可滚动的问题表：显示幕/场、节拍文本、底层校验原因，并通过现有 SelectField 选择“对白·角色 / 旁白 / 动作”。没有新增另一套页面或原生控件。
11. 人工修正只提交 `scriptDraft`，跳过剧本生成阶段，仅重新校验当前剧本并生成分镜；修正前不写入正式分集，也不调用图片、视频或配音服务。修正仍失败时继续留在问题表。
12. 草稿和恢复状态纳入工作区草稿，关闭后重新打开规划入口仍能恢复；只有通过完整校验并经用户审核的规划才能应用到正式分集。

## 五、仍需按顺序实施（本轮没有伪装成已完成）

P1：把“剧本确认”从当前合并的“剧本+分镜预览”拆成真正的用户确认阶段，并保存输入指纹与修订号，避免旧结果覆盖已修改原文。当前可在 Dialog 审核自动整理与分镜预览后应用，但还不是独立的“剧本确认”状态。

P1：将非对白类结构失败也纳入同一套草稿问题表。目前本轮针对的是 `DIALOGUE_SPEAKER_MISSING` / `CHARACTER_REFERENCE_INVALID`，无法安全转换为可编辑脚本的 Zod 结构错误仍会阻断并要求重新规划，不能伪造草稿。

P1：生成契约和持久化契约分开。当前 OpenAI 路径主要使用 JSON mode + 提示词中的 schema，Anthropic 路径传 toolInputSchema；JSON 可解析并不保证条件必填或引用有效。按供应商能力接结构化输出，不假设全部中转支持同一种 strict schema；本地语义校验必须保留。

P2：实体抽取和分场改成更小的独立阶段；超长单集按原文单元分批，并通过稳定实体表汇总，不能直接取消所有请求上限。“总集数可扩展”不等于“一次生成无限大的 JSON”。

P2：对白 delivery 演绎类型、真实 TTS 时长回写、问题修复指标和真实失败样本回归集。新增数据结构前要做旧项目兼容测试。

## 七、续推进：修正后的恢复与页面状态闭环（2026-09-28）

本次先修复前述失败草稿路径中的实际回归，不扩大为另一套 UI，也未声称独立剧本确认已完成。

### 已修复

1. **人工修正后的恢复指纹**：原实现将临时 scriptDraft 也纳入输入指纹；后续只带 resumeToken 重试时，两次指纹不一致，可能丢掉恢复入口并重跑剧本。现从来源指纹排除这个阶段载荷，仍绑定项目实质内容、原文、创作要求、目标时长与模型配置。恢复、人工修正、重生成这三类互斥请求会被拒绝混用。
2. **自动补齐及人工变化的审核记录**：人工修正不再清空之前的 adjustments。服务端用保存的草稿作为基线，合并原审核记录、人工修正差异以及本次规范化调整，并随 checkpoint 传到最终预览。
3. **明确放弃草稿的重生成**：页面发现失败草稿时，“放弃草稿重新生成”会显式提交 restart，不会再次读回同一份失败草稿。
4. **修正值持久化**：角色选择由 MotionComicPage 统一管理，变化即时保存到现有工作区草稿；关闭前再次保存。同一分集重新打开不会重置草稿或创作要求；保存失败会显示提示，并阻止以正常关闭掩盖数据丢失。
5. **状态互斥**：进入分镜恢复时同步清空本地失败剧本状态，避免下次恢复同时显示过期的对白问题。
6. **角色选择语义**：缺失角色显示“对白（待指定说话人）”，非法引用显示“无效角色”；不会在界面上默认表现为旁白。角色内心独白/画外音和动作主体保留绑定；包含冒号的合法 key 不再截断。重复 beat key 不执行批量误改。明确选无角色类型时删除字段，而非保留 undefined。
7. **问题表滚动**：问题表保留稳定高度，不会被下方原文表单挤成不可见；整体内容与问题列表各自可滚动，操作区保持在 Dialog 底部。继续复用项目 Button / SelectField，不新增原生表单控件。

## 八、独立剧本审核阶段（2026-09-28）

本节推进并替代第七节末尾的“独立剧本确认尚未完成”状态；仍沿用当前规划弹窗、分集入口、工作区草稿及服务端 checkpoint，不引入另一套项目或 Demo 页面。

### 当前实际流程

选定分集 → 生成剧本 / 实体 → 校验 → **剧本审核** →（有修改时：保存并本地重新校验 → 回到审核）→ 勾选确认 → **生成分镜** → 分镜预览 → 应用到本集。

- 首次请求显式使用 `stage: script`，服务端返回 `script-ready`，不调用分镜模型。提取独立 `generateMotionComicScript`，原 `generateMotionComicPlan` 复用它；未指定 stage 的历史调用保持兼容。
- 剧本审核显示当前集、幕/场列表、幕边界依据、剧情节拍、角色绑定、原文句段证据、实体名称及整理修改记录。可修改节拍文本、类型和角色；本轮不新增实体/造型编辑器或场次增删工具。
- 角色 / 文本修改立即写入当前工作区草稿，并标为待校验；不调用剧本模型，也不能直接提交分镜。暂时清空文本也能关闭/刷新后恢复，但空文本不能确认或成为有效 checkpoint。
- 审核通过后，需要勾选“我已核对本集剧情、角色及修改记录”，再点击“确认剧本，生成分镜”。检查勾选是当前界面的用户确认，不冒充自动语义正确性证明。
- `stage: storyboard` 必须携带已保存剧本 token；服务端继续核对原文、创作要求、项目实质字段、模型/接口与有效期。每次剧本重新校验生成新版本 token；基于旧 token 的分镜请求、携带旧 `scriptRevisionToken` 的修改均拒绝。
- 分镜成功后保留剧本 checkpoint，以便“返回修改剧本”。返回时移除旧分镜预览；修改后必须重新校验、确认、重新生成，不沿用旧分镜。
- 页面在原文/要求/时长变化、切换规划目标和修改剧本时推进请求序号；请求完成后再次核对项目快照，过时结果不进入预览。
- 审核继续使用现有 Button / SelectField / TextAreaField / CheckboxField；场次列表、节拍与修改记录分别滚动，操作区固定在弹窗底部。无图片、视频、音乐或配音调用。
