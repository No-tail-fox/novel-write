# 短片生成与 Lemo：尚未完成部分的实施方案

日期：2026-10-31（Asia/Shanghai）。本轮是方案与代码边界核查，不是新增功能完成报告。

## 1. 结论与已确认范围

不需要再搬一遍仓库，也不应重做已通过的模板和双输出。剩余重点是：普通短片补网络素材；Lemo 把官方 Agent 接成真实生产者，并补齐工具执行、阶段恢复和声音桥接；最后用真实作品、剪映和安装包验收。

- MoneyPrinterTurbo / Pixelle 共用现有“短片生成”、任务中心、素材池、时间轴和 MP4 / 剪映草稿 / 双输出。
- Pixelle 固定版本的全部 31 模板和 54 处参数继续保留；不以减少模板换稳定性。
- Lemo 留在创意视频，使用官方 SDK 与固定原版插件，不继续扩充自制小型 Agent 来替代官方循环。
- 不加入数字人直播、数字人口播、动作迁移；不横改 VOX、HTML、音乐 MV。
- 失败修程序或当前生成工程，不换样片、主题、模型或验收条件悄悄降低标准。

## 3. 工作包 A：MoneyPrinter 网络素材接入（可独立推进）

### 推荐实现

在现有本地素材池前增加“检索 → 选择 → 下载 → 托管”入口，而不是再嵌入一个完整网站或第二套生成系统。

- 增加统一素材提供商接口：检索关键词、横竖画幅、类型、时长、分页；结果统一为素材 ID、提供商、作者/来源、预览与下载信息、尺寸与时长、授权证据。
- 第一个里程碑接通一家主渠道；其它渠道使用同一契约接入。Pexels/Pixabay 是候选，是否启用以其当时官方 API、授权要求及现有专用凭据核验为准。Coverr 不列为首轮硬依赖。
- 先检查专用凭据是否已有配置；LLM 中转 key 不替代素材站 key。无凭据时明确显示未配置，仍可使用本地素材和已有生图模式。
- 自动生成检索词可以复用现有文本服务；用户文案、事实与场景约束不因检索失败被重写。支持手选与自动选材，自动选材也保留来源记录。
- 下载先进入临时文件，校验实际媒体类型、大小、画幅和时长后原子转入项目目录；防止失效链接、HTML 假视频、非预期重定向和项目外路径写入。
- 使用提供商素材 ID 与内容指纹去重；跨场景复用下载，不随导出重复下载。缓存与许可证信息绑定，不只记一个会过期的 URL。
- 未找到素材时提示具体镜头，可改检索词或导入本地素材；不能悄悄改为付费生图。

### 复用与落点

复用 `src/shared/short-video-material-runtime.ts`、`src/shared/short-video-materials.ts`、`src/shared/task-output-runner.ts`，入口沿用 `src/features/tasks/NewTaskPage.tsx`。提供商协议、主进程下载和来源清单是增量模块，不另建 task 类型或导出器。

### 验收门槛

从实际检索结果生产一支普通混剪和一支 Pixelle 模板片；二者均验证 MP4 与草稿。覆盖无结果、无 key、限流/失效链接、下载取消、重复素材、项目重开；来源可追溯，重复导出不重复下载或生成。

## 4. 工作包 B：真实模型能力与自动适配（Lemo 前置）

“自动适配”应根据已配置协议和能力探测选择路径，不是根据模型名猜接口，也不是工具调用报错后删除 tools 取得 HTTP 200。

- 普通文本服务继续保留当前 `openai / responses / anthropic` 三种适配；`src/shared/llm-protocol.ts` 已定义这三种。
- 官方 Lemo SDK 入口只接已经验证的 Anthropic Messages 通道。仅支持 Chat/Responses 的同名 Claude 模型，不据此标记兼容。
- 模型以当前渠道实际可用的 model ID 为准；用户此前提到的“Claude Opus 5.5”尚未获得本轮验证，不预置成保证可用的型号。
- 能力档案按渠道、端点、模型与关键配置版本记录：工具调用与 tool_result 往返、图片输入、流式终止与异常、实际可接受输出预算、取消行为。
- 分拆无付费的静态预检和有预算的真实最小测试；按问题定点补测，禁止 SDK 内部错误重试绕过账本。
- 4096 不再做隐形硬编码；输出预算必须可见且匹配实际能力。不支持时明确报错，不偷偷截断。`max_tokens` 结束仅代表本次响应结束，不代表创作阶段完成。
- 文案字数建议、单次 token 预算、整片时长、总费用、自动纠错次数是不同约束，分别处理；不能靠“一段超长 JSON + 放大上限”解决所有问题。

验收必须保留真实模型 ID、端点协议、工具往返及最终响应证据（脱敏），而非仅保留 200 状态码。若渠道不兼容，停止并解释具体缺项，不自动换渠道发起新的付费调用。

## 5. 工作包 C：官方 Agent 生产入口、安全工具与可靠恢复（关键路径）

### C1. 真正接上生产，而不是继续增加预检

扩展独立 worker 的 `start / resume / cancel` 契约；由主进程拥有任务、稳定 run/stage ID、配置快照、账本路径、工件与预算，SDK 负责模型—工具—反馈循环。

宿主启动只监听本机的网关，真实 API key 留在宿主；worker 只拿随机会话令牌和允许的运行目录。先仅让新创意视频任务走实验开关，旧工程保留原版本路由。不能自动把旧 unknown 请求迁移成新 run 重发。

UI 沿用现有任务状态和 StoryDream 组件，显示阶段、当前工具、产物预览、可恢复位置、错误原因与费用状态。当前网关缓冲完整 SSE，不应显示假的逐 token 进度；先显示真实阶段/工具事件，后续再单独设计流式持久化。

### C2. 保持 Agent 能力，但不直接开放整机 Shell

原版插件会要求 setup、依赖安装和工具执行。这正是必须解决的本地化适配，不是禁止全部工具后让模型继续输出文本。

- 安装器/资源准备器负责固定版本库和依赖；给 Agent 明确的库目录与可用工具，不允许上游 setup 在生产任务里自行更新到 latest。
- 原始插件与上游文件保持哈希；Windows 执行差异放宿主说明和适配层。先验证原技能能否按这些路径完成完整流程。
- 优先提供受控文件读写、列目录、渲染预览帧、渲染片段、媒体探测、读取截图、请求已配置素材/TTS 等真实工具；路径和参数由宿主验证，不把自然语言拼进任意命令字符串。
- 对 setup/deps/render/still 等固定动作做可审计的兼容桥，未批准依赖明确报错，不静默执行任意安装命令。
- 动态生成的 Node/Python 等脚本若要执行，必须先验证 Windows 系统级隔离覆盖文件访问、子进程、出网及资源限制；尚未验证时不得把 cwd、白名单或独立进程称为沙箱。
- 测试拒绝项目外写入、读取凭据/应用配置、修改宿主或上游文件、符号链接绕过、非授权联网及残留子进程。不要使用 bypassPermissions 作为解决方案。

先做隔离可行性验证，再开放相应执行能力。若某原版风格依赖暂不支持的工具，清楚列为未支持；不能宣称已完整复刻。单一受控风格可跑通也不等于全部风格通过。

### C3. 分阶段落盘，允许纠错，不强迫整片一次性 JSON

推荐流程：

需求与风格 → TREATMENT.md → 真实风格帧 → 解说文本与声音锁定 → 分镜/镜头代码与动画 → 多时刻检查和局部修复 → 最终合成与交付。

- 面向创作的 treatment、代码和素材引用允许自然文件结构；仅在阶段边界使用小型、版本化的工件清单，校验必要字段/路径/时长。
- 每一阶段记录输入指纹、产物指纹、配置、请求回执与版本；上游内容变化只失效直接依赖项。
- 渲染错误、截图或时间轴问题原样反馈给 Agent 修当前工程；模型说“完成”不能替代真实渲染与宿主验收。
- 自动纠错由阶段预算与最大轮数约束，数值是产品可见配置，不在本轮拍脑袋固化；达到阈值保留中间产物并说明下一步。
- 旧 `lemo-upstream-production.ts` 已有“本地 response.json 可恢复时不再请求模型”的语义；新官方 SDK 路线应保留这一原则，不再发明第二套收费恢复规则。

### C4. 补齐“收到响应，但作品尚未提交”的崩溃窗口

当前账本保护重复请求，但网关在收齐响应、落 received 回执后才交 SDK。需将以下状态区分开：请求已发送、结果不确定、响应已持久化、工具/工程已应用、阶段产物已验收。

- 完整响应和必要会话数据放受限的私有工件区，原子保存并校验；不写进普通诊断日志或只有哈希的账本，不保存 API key。
- 账本与工件提交建立可恢复顺序。崩溃后先查本地完整结果和 SDK 会话，不能把 received 当成作品已完成，也不能无凭据重放产生外部副作用的工具。
- unknown 默认暂停；可查询的渠道用其有效回执核对，无法核对时提示潜在重复费用并等待明确决定。换阶段目录/新 run ID 不能自动绕过。
- 取消停止新工具和后续请求，保留已收到结果；不能承诺在途远程请求一定已经撤销或不计费。

故障注入至少覆盖：发送前、上游响应中断、终止回执到达后、回执落盘后但交 SDK 前、工具完成但阶段未提交、应用重启。验收结果要证明既不盲重发，也不丢失可恢复产物。

## 6. 工作包 D：宿主配音、字幕和最终混音（紧随生产接线）

推荐按用户提出的方向明确分工：Agent 负责创意、分镜、画面代码与画面纠错；程序调用已有配音服务，负责字幕对齐、时间轴和最终混音。AI 可以提出配乐/音效意图，但不能自行再生成另一套主配音。

- treatment 与风格帧先确认；旁白定稿后由宿主生成 TTS 并测量真实时长，再锁定镜头窗口和字幕 cue，交给 Agent 制作动画。
- 只有一个权威时间轴；MP4 与草稿读取相同 cue、素材和场景时长，不分别重建时间轴。
- 每次交付只有一个最终混音责任方。Lemo 视觉片段不携带重复旁白、重复 BGM 或烤死的同一套字幕；合法的画面内标题与独立字幕需区分。
- 音效可作为独立轨工件提交给宿主，不能在视觉视频中暗藏重复音轨；允许明确标注需要保留的原声素材。
- 文字不变且声音配置不变复用 TTS；换模板不重做声音；换 BGM 不重做生图/TTS；修改旁白才使受影响的时长、字幕和镜头窗口失效。
- 将现有 `short-video-render.ts` 的真实音频测长和对齐、旧 Lemo 的已批准字幕/绝对时间窗语义接入新链路，不另建第二套导出时钟。

验收：无双配音/双字幕/重复混音，首中尾听审，切镜与字幕窗口正确，输出存在预期音轨；故意触发一个交付分支失败后，只恢复该分支，不重做付费素材。

## 7. 工作包 E：真实验收与安装发行（实现与验证分开列）

### E1. Pixelle 剩余项主要是交付验证，不再重写模板

- 保持原 31 模板及 54 参数；固定输入工程回归继续保留。
- 在剪映应用实际打开全部模板代表工程，逐项检查丢素材、时间轴、中文字体、音轨和编辑边界；只有真实应用检查才关闭此项。
- HTML/动画烘焙成视频的部分明确标注“片段可替换、内部图层不可原生编辑”；字幕、配音等独立轨按实际输出验证，不能承诺所有图层可编辑。

### E2. Lemo 原创实片验收

先锁定一支 15–30 秒真实原创 brief，用一个实际已验证模型完成全部阶段；保存 treatment、真实风格帧、源码、工具调用、纠错记录、成本回执、MP4 与检查图。此后增加不同风格及较长时长案例，不能拿官方 demo 或离线假响应替代。

技术与审美分开评估：可播放/音画同步是技术门槛；构图、材质、运动、节奏、信息层级和镜头连贯是视觉门槛。与上游参考片采用相近时长和风格逐段对照，但不假称已经达到同等效果。

### E3. 全局界面和故障恢复

既有 404 项是指定 17 文件的回归数字，不自动覆盖历史全部问题。历史“6 项全局界面契约失败”需要找回测试名与原始失败日志，逐项关联修复后证据；证据不明确时保持待核对，不能重新编出 6 个失败。

覆盖普通/紧凑窗口、加载/空态/错误/取消/部分成功/unknown、重复点击、重开工程、旧任务兼容。新增 UI 继续使用 `src/ui`、现有路由、稳定任务 ID 和状态所有者，不额外嵌入 Streamlit。

### E4. 安装器与运行资源

补齐固定版本的 Node、官方 SDK/CLI、worker、Python、FFmpeg、浏览器和字体资源发现与校验；逐项确认复用、随包或按需下载策略、许可要求和实际体积，不假设用户预装开发环境。

优先采用首次使用创意视频时准备可选 Lemo 运行包的产品方向，但仍需验证下载源、完整性、断点续传、版本回滚和离线导入；网络不可用时明确阻断，不在后台无限下载。原生 CLI 体积不可忽略，不承诺零体积移植。

在无开发环境的干净 Windows 用户环境测试：首次安装、中文/空格路径、取消、重开恢复、运行包缺失/损坏、磁盘不足和卸载保留工程。空间预检按实际下载、解包、渲染峰值估算，不以一个任意固定数字替代。

## 8. 实施顺序与停止条件

遇到不兼容渠道、未知付费结果、缺少工具隔离、缺素材或缺安装资源，展示具体阻断项并保留现有工程；不自动改模型、改样片、删模板、降低验收标准。
