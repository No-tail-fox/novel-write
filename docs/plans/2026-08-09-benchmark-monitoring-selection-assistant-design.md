# StoryDream 对标监控与选品助手设计

日期：2026-08-09  
状态：已评审，首个可用版本已实现  
参考：用户提供的 Storybound 对标监控截图、StoryDream 现有 Electron 工作台、现有选品助手/对标导入/爆款拆解功能

## 1. 结论

保留现有两个侧栏入口和稳定路由 ID，但升级职责：

- `benchmark`：侧栏文案由“对标导入”改为“对标监控”，负责跨平台账号监控、作品发现、趋势判断、筛选与批量入池。
- `book-selection`：继续叫“选品助手”，从本地商品资料表升级为候选池、证据评分、对比决策和创作简报工作台。
- `viral-analyzer`：继续负责单作品深度拆解，不在对标监控里复制下载、转写、关键帧和爆款结构分析。
- `new-task`：继续作为最终生产入口，接收选品、对标样本和创作简报。

核心闭环：

```text
添加三平台对标组
  -> 首次同步并建立账号基线
  -> 发现异常高表现作品
  -> 收藏/打标/批量加入候选池
  -> 选品助手聚合机会信号
  -> 对比评分并生成创作简报
  -> 深度拆解或创建新任务
```

## 2. 产品边界

### 对标监控回答什么

- 最近哪些账号或作品涨得异常快？
- 同一主题在抖音、视频号、B 站分别怎么表达？
- 哪些标题、开头、时长、发布时间和话题值得继续研究？
- 哪些作品值得进入爆款拆解或选品候选池？

### 选品助手回答什么

- 当前有哪些商品/图书值得做？
- 机会来自哪些真实对标作品和趋势证据？
- 竞争是否已经拥挤，当前账号是否适合做？
- 最值得采用的卖点、受众、内容角度和对标样本是什么？
- 决定做以后，如何一键形成可执行的创作任务？

### 本轮不做什么

- 不把自动发布、自动评论、私信获客写入首期。
- 不承诺无法验证的“全网实时数据”；默认是定时或手动同步。
- 不通过绕过平台风控、复用私有接口或保存明文 Cookie 来伪造稳定采集能力。
- 不把缺失指标当作 `0`，不把不同平台含义不同的指标强行相加。
- 不在对标监控重复建设现有爆款拆解报告。

## 3. 三平台链接模型

### 3.1 跨平台对标组

一个对标组表示同一品牌、作者、赛道或竞争对象，固定显示三个链接位：

| 平台 | 链接类型 | 首期输入 | 状态示例 |
|---|---|---|---|
| 抖音 | 账号主页链接 | 主页分享链接或可识别账号链接 | 正常、需登录、链接失效、同步受限 |
| 视频号 | 账号主页/作品分享入口 | 可识别分享链接；无法解析时允许手工补账号名和备注 | 正常、需登录、仅手工、同步受限 |
| B 站 | UP 主空间链接 | `space.bilibili.com/...` 或可识别空间链接 | 正常、链接失效、限流、同步受限 |

录入规则：

- “添加对标组”弹窗同时展示抖音、视频号、B 站三个独立输入框。
- 至少填写一个链接即可保存，缺失的平台保留“未添加”位置，不隐藏。
- 粘贴后立即识别平台、账号/作品类型、规范化 URL，并显示可验证结果。
- 如果用户粘贴的是作品链接，提示“这是单作品链接”，可选择“单视频解析”或从作品反查账号后加入。
- 三个平台分别保存同步状态和错误，不因其中一个失败阻塞另外两个。
- 允许给对标组设置名称、赛道、标签、监控频率和备注。

### 3.2 单视频解析

顶部保留独立“单视频解析”动作：

- 支持抖音、视频号、B 站作品链接。
- 自动识别平台；识别失败时允许手动指定。
- 基础解析完成后可选择“保存到对标监控”“加入候选池”“进入爆款拆解”。
- 已存在的作品按规范化链接或平台作品 ID 去重，不制造重复记录。

## 4. 对标监控功能

### 4.1 账号与分组管理

- 新建、编辑、归档对标组。
- 一个对标组绑定三平台账号链接。
- 按赛道、品牌、作者、主题和自定义标签分组。
- 账号搜索、收藏、置顶和批量刷新。
- 每个平台显示最后同步时间、采集范围、基线样本数和异常状态。
- 监控频率建议：手动、每 6 小时、每天；桌面首期只保证应用运行期间调度。
- 账号历史不可因改名丢失，内部始终使用稳定账号 ID。

### 4.2 作品信息流

每条作品显示：

- 平台、账号、封面、标题/正文摘要、发布时间、时长、话题标签。
- 平台原始指标与统一摘要指标。
- 爆发表现倍率、账号内百分位、趋势方向和评分置信度。
- 收藏、标签、备注、已拆解、已入选品、已创建任务等工作状态。
- 快捷动作：深度拆解、加入候选池、复制链接、提取文案、标记不相关。

批量动作：

- 加入候选池。
- 添加标签。
- 提取文案。
- 进入拆解队列。
- 导出 CSV/JSON。
- 标记已读或排除。

### 4.3 筛选与排序

基础筛选：

- 平台：全部、抖音、视频号、B 站。
- 对标组、账号、赛道、标签和收藏状态。
- 发布时间：24 小时、7 天、30 天、自定义。
- 时长区间、标题关键词、话题标签。
- 是否已拆解、是否已入选品、是否已有文案。

表现筛选：

- 点赞、评论、收藏、转发、播放量等平台可用指标。
- 互动率、爆发倍率、账号内百分位、增长速度。
- 仅看异常上涨、仅看新发布、仅看高置信样本。
- 排序：最新、爆发分、互动率、播放/点赞/评论、账号内增幅。

筛选条件可保存为视图，例如“7 天内 B 站高收藏”“视频号高转发”“抖音图书带货”。

### 4.4 趋势与预警

- 账号趋势：发布频率、互动中位数、爆款率、主题分布。
- 主题趋势：同一关键词跨账号、跨平台的作品数量与互动变化。
- 异常作品：以短趋势线、异常标记和文字原因展示，不使用大仪表盘。
- 提醒类型：新爆款、连续上涨、竞品突然高频发布、某主题跨平台同时升温。
- 提醒中心支持已读、稍后处理、静音和跳转到原始证据。
- 首期提供应用内提醒；系统通知和日/周报放到后续版本。

### 4.5 详情检查器

点击作品后，主列表保持选择高亮，右侧打开详情检查器：

- 基础信息与原始链接。
- 分平台原始指标、快照时间和缺失原因。
- 账号基线对比和爆发分解释。
- 标题、话题、文案、关键帧摘要。
- 关联商品/图书、标签和个人备注。
- 历史快照趋势。
- “进入爆款拆解”“加入选品候选”“创建任务”主动作。

鼠标选择不抢走搜索框或备注输入焦点；键盘选择才按可访问性规则移动焦点。后台刷新只更新数据，不自动滚动列表。

## 5. 跨平台指标合同

### 5.1 统一字段

所有作品都有：

- `platform`、`platformPostId`、`accountId`、`canonicalUrl`。
- 标题/正文、发布时间、时长、封面、话题标签。
- 指标快照时间、采集来源、可用性和置信度。
- 收藏/标签/备注/处理状态等本地工作字段。

### 5.2 平台原始字段

| 平台 | 主要原始指标 | 注意事项 |
|---|---|---|
| 抖音 | 点赞、评论、收藏、分享；播放量和粉丝量按可用性记录 | 不可见字段显示“—”和原因，不补零 |
| 视频号 | 喜欢/推荐、评论、转发等可见互动；播放和账号数据按来源记录 | 登录态和链接可解析性可能限制自动同步 |
| B 站 | 播放、弹幕、点赞、投币、收藏、评论、分享、粉丝量 | 投币与弹幕是平台特有信号，保留原始含义 |

### 5.3 可比较指标

- `engagementTotal`：仅对明确可加总的公开互动做平台内汇总，不作为跨平台绝对排名。
- `engagementRate`：有可靠播放量或粉丝基数时才计算，并显示分母。
- `accountPercentile`：作品在该账号同平台近期样本中的百分位。
- `velocity`：单位时间内的互动增长，要求至少两个有效快照。
- `burstScore`：根据作品年龄、账号基线、平台内百分位和增长速度计算的 `0–100` 分。
- `scoreConfidence`：高、中、低；样本不足或关键指标缺失时自动降低。

缺失值是 `null + reason`，绝不能写成 `0`。跨平台比较优先使用“相对自身账号基线”和“平台内百分位”，不直接比较绝对点赞数。

## 6. 爆发分建议

首期使用可解释规则，不使用黑盒结论：

```text
爆发分 = 35% 账号内互动百分位
       + 25% 作品年龄校正后的增长速度
       + 20% 评论/收藏/转发等深互动质量
       + 10% 主题近期升温程度
       + 10% 跨平台复现信号
```

降权条件：

- 账号基线少于 10 条作品。
- 只有单次快照，无法判断增长速度。
- 关键指标不可见或来源为手工补录。
- 作品发布时间无法确认。

UI 必须展示“为什么是 82 分”，例如：

> 账号近 30 条作品中排名前 5%，发布 8 小时互动速度为中位数 3.2 倍；B 站同主题本周同步升温。置信度：中。

## 7. 选品助手功能

### 7.1 候选来源

- 从对标监控批量加入。
- 从单视频解析或爆款拆解加入。
- 手工新建商品/图书。
- 从 CSV/JSON 导入。
- 从已有创作任务或历史选品复制。

### 7.2 选品资料

保留现有字段：主题、商品/书名、作者、分类、关键词、价格、目标人群、人物、年代/场景、链接、核心卖点和备注。

新增字段：

- 选品状态：候选、观察、计划创作、已创作、淘汰。
- 商品类型、平台来源、佣金/毛利（用户手工填写）、库存/时效备注。
- 内容适配赛道、适合账号、禁用表达和合规风险。
- 关联对标作品、趋势信号、爆款拆解报告和历史任务。
- AI 建议卖点、反对理由、内容角度和证据引用。
- 用户评分、最终决策和决策备注。

### 7.3 机会评分

默认总分 `0–100`，用户可以调整权重：

```text
机会分 = 30% 需求热度
       + 25% 内容缺口
       + 20% 当前账号匹配度
       + 15% 转化证据
       + 10% 执行成本反向分
```

每一项必须引用证据：

- 需求热度：相关主题作品数量、增速、深互动和跨平台复现。
- 内容缺口：高需求但同质内容少，或现有内容存在明显未覆盖角度。
- 账号匹配：当前账号历史主题、人物素材、受众和视频形式。
- 转化证据：卖点提及、评论购买意图、用户录入的佣金/价格/销量证据。
- 执行成本：素材可得性、合规风险、脚本难度和制作时长。

AI 建议只提供评分草稿，用户可覆盖每项分数和权重；最终分必须标明“自动建议”或“人工确认”。

### 7.4 决策工作流

- 候选池：高密度表格，支持筛选、排序、收藏和批量状态变化。
- 对比台：最多并排 4 个选品，按机会分、证据、风险、卖点和制作成本精确比较。
- 详情检查器：编辑资料、查看证据、调整分数和关联对标作品。
- 淘汰记录：保留淘汰原因，避免团队后续重复评估。
- 保存视图：例如“高机会低成本”“图书带货待验证”“B 站适配”。

### 7.5 创作简报

从确定的选品生成一份可编辑简报：

- 核心受众与购买动机。
- 主卖点、辅助卖点和不可说内容。
- 推荐标题方向、前三秒开头和结构节奏。
- 推荐时长、比例、平台和发布窗口。
- 参考对标作品及采用/避开的部分。
- 建议素材、人物、画面风格和声音风格。
- 风险检查与待人工确认项。

简报动作：

- 带入“新建任务”。
- 选择一条样本进入“爆款拆解”。
- 保存为提示词模板。
- 复制 Markdown/导出 JSON。

## 8. 页面信息架构

### 8.1 对标监控页

```text
全局侧栏 236px
┌─────────────────────────────────────────────────────────────────┐
│ 页面工具栏：平台分段控件 | 作品/账号/趋势 | 单视频解析 | 添加对标组 │
├──────────────┬──────────────────────────────────────────────────┤
│ 对标组栏     │ 指标摘要 / 筛选 / 排序 / 保存视图                │
│ 搜索与标签   ├──────────────────────────────────────────────────┤
│ 三平台状态   │ 批量选择工具栏                                   │
│ 最后同步     ├──────────────────────────────────────────────────┤
│              │ 作品列表或账号列表                               │
│              │ 选中作品时右侧滑出详情检查器                     │
└──────────────┴──────────────────────────────────────────────────┘
```

设计细节：

- 平台用文字 + 小图标分段控件，选中态沿用珊瑚红，不复制 Storybound 绿色。
- 对标组栏宽约 280px；主列表占剩余空间；详情检查器宽 360–420px。
- 作品是重复实体，可以使用低圆角行卡；页面区块不做浮动卡片。
- 指标摘要用紧凑数据条，不做装饰性大数字卡阵列。
- 主动作固定在右上，批量动作只在有选择时出现且不改变列表几何。

### 8.2 选品助手页

```text
全局侧栏 236px
┌─────────────────────────────────────────────────────────────────┐
│ 候选池 / 对比台 / 创作简报 | 保存视图 | 导入 | 新建选品          │
├───────────────────────────────┬─────────────────────────────────┤
│ 候选表格/对比区               │ 详情检查器 360–420px            │
│ 名称、机会分、状态、趋势证据   │ 资料 / 评分 / 证据 / 风险       │
│ 卖点、成本、最后更新           │ 生成简报 / 带入新任务           │
└───────────────────────────────┴─────────────────────────────────┘
```

设计细节：

- 候选池默认是表格，不使用松散卡片墙。
- 分数同时显示数值、证据完整度和人工确认状态。
- 证据点击后定位到对应对标作品，不只显示 AI 摘要。
- 对比台最多 4 项，超出时要求替换，不横向无限扩张。
- 紧凑窗口保留图标侧栏，详情检查器改为覆盖式抽屉，主表格允许横向滚动但固定名称/分数列。

## 9. 权威状态与交互合同

### 对标监控

```text
selectedBenchmarkGroupId
selectedAccountId
selectedPostIds
primarySelectedPostId
platformFilter
savedViewId
detailInspectorOpen
selectionOrigin: pointer | keyboard | programmatic
pendingNoteEdit
```

- `primarySelectedPostId` 同时驱动列表高亮、详情标题、指标、文案和路由深链。
- 多选时保留一个主选项用于详情，批量动作作用于 `selectedPostIds`。
- 后台同步不得清空当前选择；作品确实被删除时才回退到最近邻项并提示。
- 未保存备注在切换选择时保存草稿，不静默丢失。

### 选品助手

```text
selectedSelectionId
comparisonSelectionIds
activeSelectionTab: profile | score | evidence | brief
selectionFilters
scoreDraft
pendingEditState
```

- 表格、详情、对比台和创作简报始终引用稳定选品 ID。
- 选择证据时打开来源作品并保持返回路径。
- 调整权重或分数先进入草稿态，明确保存后才改变正式机会分。

## 10. 状态与异常

必须设计并验证：

- 首次空状态：提供“添加对标组”和“解析单视频”，不展示营销说明。
- 首次同步：显示平台分别进行到哪一步，已完成的平台立即可用。
- 部分失败：抖音成功、视频号需登录、B 站限流时，保留成功数据并提供各自重试。
- 样本不足：爆发分显示“基线不足”，仍可查看原始指标。
- 指标缺失：显示“—”及原因，排序时放在有效值之后。
- 链接重复：定位到现有账号/作品并提供加入当前分组。
- 内容删除或私密：保留历史快照和本地备注，标记来源不可访问。
- 离线：可浏览本地缓存和编辑标签/备注，暂停同步动作。
- 需登录：明确登录入口、会话作用域和过期状态，不要求用户粘贴明文 Cookie。
- 同步限流：显示下一次可重试时间，不自动高频重试。
- 选品无证据：允许保存，但机会分标为低置信并列出待补项。

## 11. 数据实体建议

| 实体 | 关键字段 | 用途 |
|---|---|---|
| `BenchmarkGroup` | id, name, track, tags, refreshPolicy | 跨平台对标组 |
| `BenchmarkAccount` | id, groupId, platform, canonicalUrl, externalId, syncState | 三平台账号 |
| `BenchmarkPost` | id, accountId, externalId, canonicalUrl, content, publishedAt | 作品权威记录 |
| `BenchmarkSnapshot` | postId, capturedAt, metrics, availability, source | 原始指标快照 |
| `BenchmarkSignal` | id, type, score, confidence, evidencePostIds | 异常/趋势证据 |
| `SelectionRecord` | id, productInfo, status, score, manualOverrides | 选品资料与决策 |
| `SelectionEvidence` | selectionId, signalId/postId, note, weight | 选品证据 |
| `CreativeBrief` | id, selectionId, content, sourcePostIds, version | 创作交接 |

现有 `BookSelectionRecord` 在实现时可兼容迁移到 `SelectionRecord`，保留旧 `theme + bookId` 的稳定身份或建立一次性映射，不丢历史选品。

## 12. 首期范围

### P0：数据接入验证

- 验证三平台账号主页/作品链接的规范化和可采集字段。
- 明确视频号登录态、链接类型和失败回退方案。
- 复用现有爆款拆解的抖音/B 站单作品能力，形成统一连接器接口。
- 确认本地会话、频率控制和平台条款边界。

### P1：可用 MVP

- 三链接对标组管理。
- 手动刷新和应用运行期间的定时同步。
- 作品列表、平台原始指标、基线和可解释爆发分。
- 平台/时间/账号/关键词/表现筛选与保存视图。
- 收藏、标签、备注、批量加入候选池。
- 单视频解析并跳转现有爆款拆解。
- 选品候选池、机会评分、最多 4 项对比。
- 证据详情、创作简报、带入新建任务。
- 空、加载、部分失败、需登录、限流和离线状态。

### P2：增强

- 趋势页、跨平台主题聚类和应用内提醒中心。
- 日报/周报、系统通知和导出。
- AI 自动归纳卖点、反对理由和内容缺口。
- 评分权重模板、团队赛道模板和更完整的合规检查。

### P3：协作与规模化

- 多设备/团队同步、批注、负责人和审核流。
- 云端持续监控、稳定任务调度和角色权限。
- 与发布数据回流形成“选品 -> 创作 -> 发布 -> 复盘”的闭环。

## 13. MVP 验收标准

- 可以创建一个同时包含抖音、视频号、B 站链接位置的对标组，每个平台独立验证和同步。
- 任一平台失败不影响另外平台的数据浏览和操作。
- 作品列表可按平台、时间、账号、关键词、收藏、爆发分和平台原始指标筛选/排序。
- 缺失指标不显示为 `0`，并能查看缺失原因和采集时间。
- 选中作品后列表、详情、文案、指标和深链保持同一作品 ID。
- 可以批量把作品加入选品候选池，并在选品详情中回到原始证据。
- 机会分可解释、可人工覆盖、显示置信度，最多并排比较 4 项。
- 可以从选品生成创作简报，并带入现有新建任务。
- 可以从对标作品进入现有爆款拆解，不创建第二套拆解报告。
- 1440×900 与 1080×720 桌面窗口无控件重叠、文字裁切和不可控的嵌套滚动；键盘操作、焦点可见和 reduced motion 合格。

## 14. 视觉方向

- 沿用 StoryDream 的深色中性表面、珊瑚红主操作、蓝色趋势、琥珀色提醒和绿色成功状态。
- 沿用 4–6px 圆角、细分隔线、紧凑 12–16px 工作区字号和 Lucide 图标。
- 不复制 Storybound 的绿色品牌色，不使用玻璃拟态、紫色渐变、装饰光斑或营销式大标题。
- 以分隔线、对齐和字号层级组织页面；卡片只用于重复作品/候选实体，不嵌套卡片。
- 所有指标都以数字和文字表达，颜色只作为辅助信号。
