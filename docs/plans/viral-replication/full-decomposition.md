# 整条视频的全维度拆解规格

日期：2026-09-16。用户已纠正方向：**要整体拆解，复刻是拆解后的用途。** 本文是 M1 的产品范围和算法主规格；其他文档的数据、工程、预算和验收须遵循此处定义。所有能力均为待实现方案。

## 1. “整体”同时指全时长、全要素、全局关系

导入一条视频，默认拆解从第一帧到最后一帧。结果需要同时回答“讲了什么”“每个镜头怎样做”“画面、文字、动作、声音如何配合”“整条片如何形成节奏与风格”。用户可选一个区间深入查看，但系统不能只分析开头或抽几张图后称为完整拆解。

| 拆解维度 | 具体输出 | 证据形式 |
| --- | --- | --- |
| 全片概况 | 时长、比例、帧率、结构类型、主要角色/对象、整体视觉风格、主题与受众推断 | 媒体探测、全片观察汇总；推断单列 |
| 内容与叙事 | 逐字稿、开头钩子、观点/信息点、铺垫、证据、冲突、转折、结尾/CTA、段落关系 | 原音区间、字幕/画面引用、关联镜头 ID |
| 逐镜头 | 每个镜头起止、时长、景别、对象、主体动作、镜头功能、是否插入 B-roll | 来源连续片段、首/中/尾关键帧、边界依据 |
| 构图与摄影 | 主体位置、前后景、层次、视线方向、留白、光色、推拉摇移/缩放、镜头运动与主体运动的区分 | 同镜连续帧、主体位置轨迹/运动证据；无法区分时标记 |
| 文字与版式 | 字幕逐句起止、屏幕文案、文字位置/相对尺寸/颜色/层级、强调、出现/消失方式、安全区 | OCR 框与时间、图像裁剪、原视频回放；具体字体未知时给近似类别 |
| 剪辑与转场 | 硬切、叠化、擦除/遮挡/闪白等候选，前后镜关系、转场时长、节奏变化 | 边界两侧及过渡期连续帧；低置信度可人工修订 |
| 动效与合成 | 对象/图层的入场、变化、停留、退场，位移/缩放/透明度/旋转、文字动画、相机与图层的配合 | 时间事件、屏幕归一坐标、起终状态和回放证据；“可能实现方法”与观察分开 |
| 声音 | 旁白/对白、说话人、语速/停顿、配乐起止/能量变化、节拍候选、音效类型/落点、音量关系 | 实际音频片段、波形/响度/频谱、ASR/音频理解；不能由静帧想象声音 |
| 音画关联与节奏 | 哪个词触发切镜/强调/动效、音效是否压在动作落点、卡点剪辑、信息密度、镜头时长曲线、情绪与节奏转折 | 多轨同一原片时钟、关联事件 ID、时间差；因果解释另列 |
| 全片制作蓝图 | 叙事骨架、镜头节奏表、字幕/配色/动效规则、素材清单、音轨编排、可替换项、迁移建议 | 从已拆解事件汇总，可下钻到原片；作为后续复刻输入 |

整体拆解不等于从成片恢复原始 AE/剪辑工程。原始图层、素材来源、精确字体、关键帧曲线、被遮挡内容或混音分轨可能不可恢复；结果给出观察、可信程度和可近似实现的方法。不能把无法恢复当成完全不分析该维度，也不能把推测写成已检测事实。

## 2. 用户拿到的结果

主界面提供“全片总览 / 逐镜头 / 视听时间线 / 制作蓝图”四个视图，共享同一来源数据与稳定选中 ID。

- **总览**展示叙事段落、镜头时长/信息密度曲线、全片风格，以及尚待补充的区间或维度。
- **逐镜头表**可按原片顺序展开，字段包含缩略图、起止/时长、台词、景别/构图、动作/运镜、屏幕文字、转场、音效、作用与复刻建议。
- **多轨时间线**至少有镜头、台词、屏幕文字、转场/动效、配乐、音效；点击任何事件都回放原片对应区间。拖动时间游标时显示该时刻所有轨道的关系。
- **制作蓝图**给出整体规则和局部例外：例如“开头快速切镜，解释段留阅读时间，转折处音乐降下、文字放大”。每条结论附对应原片事件，不只给抽象建议。

用户可修改镜头边界、补记漏掉的短动作/声音、修订 OCR 和说话人、接受或否定解释。改一个边界只重算相邻镜头及跨边界关系；人工修改可追溯，不因后台重试被覆盖。复制台词、导出镜头表/JSON/Markdown 报告、保存模板都可以在没有新配音/新成片时独立完成。

## 3. 完整处理流程

### A. 全片基础扫描

托管导入/下载文件，探测容器、音轨和旋转，以媒体 PTS 建立统一毫秒时钟。默认分析范围为完整文件。既有下载平台范围不变；本地按实际文件大小、空闲磁盘、解码能力和预计工作量预检，资源不足在模型调用前说明，不设置任意时长或 1 GiB 产品硬上限。所有长片处理流式分块，不能将整个视频读入内存。

本地扫描覆盖所有解码帧，低分辨率 scene score、直方图变化和黑帧/闪白候选用于找视觉边界；不先把整片降到 4 fps 再称为逐镜头扫描。阈值只是候选规则，运动镜头/闪光/叠化可能误判，后续根据边界连续片段复核。音轨做全程能量、静音、语音活动区间和节拍候选分析。OCR 按镜头及画面变化自适应采样并跟踪文本变化，不只认一张封面。

### B. 分批视听理解

扫描之后建立确定性窗口清单。初始单批核心时间最长 30 秒，前后各带最多 1 秒上下文，所有核心区间的并集必须覆盖整个分析范围，无洞、无重复归属。

单批先按镜头/事件组织最多 16 个观察单元，每单元多图请求最多 4 帧，合计最多 64 张/引用。候选过密时继续拆小批次，不能为了 16 个单元把真实镜头吞掉。慢动作/长镜头也应分成对象状态变化单元。静帧只支撑外观；连续动作和转场必须有短片段/足够密集的帧序列证据。

Provider 支持原生视频理解时，按其时长/分辨率/音轨能力提交局部片段；只支持多图时，运行有序帧观察并由本地运动测量补证据。两条路径输出同一契约，能力差异体现在 coverage 与置信度，不能把多图看不到的连续变化写成确定结论。

原片 ASR 按 Provider 上限分段并在静音附近切分；保存全局绝对时间，窗口重叠文字经时间和原文去重。音频理解与 ASR 分开：通过真实声音片段判断旁白、音乐、环境音、拟音，辅以能量/节拍/瞬态测量。无法从混合音轨可靠分辨时标“混合音轨待复核”；精确乐曲识别、乐器分离或原始 stems 不作为必需前提。

### C. 合并与全片关系分析

观察窗口保存独立产物。边界事件按原时间、对象、文本和媒体证据匹配归并，不能只用相同描述去重；归属主窗口的 core range，context 中的同一事件只补证据。跨窗持续的音乐/字幕/长动作保留一个逻辑 ID 和多个证据段。

先汇总各叙事段，再形成全片结构、节奏、视觉风格与声音风格。全局模型只引用已完成的镜头/事件 ID；单镜头不需要背整部片的原始帧数据。保存摘要层次和输入 hash，局部修改只失效关联摘要及全片结论。

音画关系由同一时钟做候选关联，再由模型/人工说明作用，例如 `word → title-emphasis`、`cut → beat`、`impact → sfx`。时间接近是关联证据，不自动证明创作者意图或观众心理。

### D. 可编辑报告与蓝图

先生成**拆解文档**，它在没有新稿的情况下就能独立使用。再从用户接受的拆解中提取可复用规则和复刻蓝图。新稿、语义锚点、素材替换和导演工程属于后续制作层，不能成为查看完整拆解的先决条件。

## 4. 覆盖率、预算与恢复

原先“64 帧、16 请求”只保留为单批资源控制，不能作为全片完成条件。模型预算由全片扫描结果决定：批次数、各批视觉/音频请求、ASR 长度、OCR 路径、汇总层级、可能修复次数分别列出。单次估价不足时显示待分析范围及维度，用户可提升预算继续或保存部分结果；不能偷偷改为只分析前 120 秒。

每个区间的每个维度保存 `pending / running / analyzed / needs-review / unavailable / not-applicable` 和证据密度。区分：

1. **扫描覆盖**：是否从头到尾处理了本地媒体。
2. **模型处理覆盖**：各轨道区间是否已执行所需理解步骤。
3. **证据/识别质量**：哪些结论可信、哪些需要人工复核。

“全程已处理”不表示所有推断准确；“待复核”不等于没有分析。缺少整段声音或动作分析能力时必须显示缺口。存在 pending/running 区间时，不展示“整体拆解完成”；生成部分报告不等于任务失败，也不能丢掉已完成内容。

每个窗口、轨道和汇总层分别 checkpoint，输入依赖包括源 hash、时间范围、采样规划、Provider/模型/提示版本及相邻上下文 hash。付费请求默认不自动重发；未知结果先对账。全片执行期间的预算消耗不会因为恢复或进入下一个窗口而重置。

## 5. 实施拆分

| 工作包 | 产物 | 与现有代码的衔接 |
| --- | --- | --- |
| P04a 全片扫描 | 镜头候选、音频分段、文字变化候选、窗口清单 | `viral-runtime.ts` 的 FFmpeg/ASR 接点；新增 `viral-deep-analysis.ts` 组织 |
| P04b 镜头与视觉观察 | 全部镜头、构图/主体动作/运镜、文本版式、转场/动效事件 | 新的结构化视觉输出，替换新路径中“不分析动效”的限制；旧 quick 仍可用 |

| P04d 全片汇总 | 跨窗事件合并、叙事/风格/节奏总览、覆盖矩阵、制作规则 | 分层汇总与独立拆解文档；新稿蓝图作为下游派生产物 |
| P05 结果工作区 | 总览、逐镜头表、多轨时间线、证据检查器、人工修订和导出 | 扩展 `ViralReport.tsx`/蓝图视图，复用 `src/ui` 与原片播放器 |

P01/P03 的契约与持久化应先支持独立拆解文档，再承载复刻蓝图。M1 以“整体拆解报告独立可用”为完成点；M2 才验收新配音、ShotCraft、导演工程与三个开头；M3 为可选 Hypit 执行。

## 6. 必须证明整体拆解有效的案例

- 一条包含口播、B-roll、屏幕文字、明确转场、音乐起落、动作音效的自制参考片，人工标注全片镜头与多轨事件；比较遗漏、误报和源时间误差。
- 一条超过 120 秒、含跨窗口长音乐和长镜头的参考片，验证从首帧到尾帧都可下钻，窗口边界无丢失/重复、预算汇总正确。
- 一条无旁白、主要靠画面/音乐/文字表达的片，验证不会因为没有口播而只返回空白蓝图。
- 快切、混合音轨、低清字幕分别制造难例，要求报告标出证据限制；不能以强行猜测“提高完成度”。

量化标准见 [验收方案](acceptance.md)。20–30 秒新片及 A/B/C 三个开头仍作为后续复刻层验收，与这些整片拆解案例独立计量。
