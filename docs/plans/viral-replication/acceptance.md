# 产品流程与验收方案

日期：2026-09-16。本文件是待实现规格。用户已确认：按可对外收费分发设计，先完成一条 20–30 秒中文解说片，再扩展三个开头版本。下文的精度、性能和画面标准均为验收目标，本轮没有生成样片或运行这些测试。

## 1. 首期范围与成功定义

M1 首先让用户拿到整条视频的完整拆解，不依赖新稿或新片生成：全片结构、逐镜头、构图运镜、字幕版式、转场动效、声音以及音画节奏都有可定位的结果。M2 再用新主题、文案和素材形成原生可编辑工程。整体拆解的 D 系列验收和复刻的 A 系列分别通过；播放量、完播率和爆款概率不作为功能承诺。

| 项目 | 首期约定 |
| --- | --- |
| 参考片 | 默认完整原片，无 10–120 秒或口播题材限制；链接入口沿用现有平台支持，增加本地视频；长片分批处理 |
| 输入质量 | 不设强制 720p 门槛；可解码的低清视频允许导入，小字、遮挡和快切导致的不可判读处明确标记 |
| 快速分析 | 默认 8 帧、最多 40 帧，保留现有报告与模板出口；不能据此宣称完整识别镜头和动效 |
| 整体拆解 | 全片扫描＋逐批多维分析＋跨批汇总；64 帧/16 单元/16 次初始视觉调用是单批资源起点，不是整片上限；声音与连续视频按 Provider 能力另计，预算消耗全片累计 |
| 首条输出 | 20–30 秒、中文解说、9:16、1080×1920、24 fps，沿用现有导演导出；首条打通后补 16:9 回归；30 fps 仅测试求解器/模板，产品选项另列扩展 |
| 首批变体 | A 为已验收原版，再产生 B、C 两个开头版本，共 3 个输出；正文不改，分别保留工程快照 |
| 制作路径 | 自有蓝图与语义时序 → 现有 Editorial 工程 → 导演工作台 → 当前导出链路；Hypit 不作为首期安装、运行或分发依赖 |

默认范围为完整 `[0,durationMs)`，局部聚焦用于查看和补证据，不改变整体报告的覆盖要求。超出一批的资源就拆批，不能静默删镜头、漏轨道或截掉后半段。预算不足时保留部分结果和覆盖矩阵，允许继续；不把部分处理报告标为完整。全部范围和费用在派发前可查看。

### 1.1 整体拆解的独立验收（M1）

| 编号 | 检查项目 | 通过标准 |
| --- | --- | --- |
| D01 | 全时长 | 使用一条超过 120 秒且含跨窗口事件的夹具；扫描范围、计划窗口核心范围均完整覆盖原片，首尾可回放，区间空洞为 0；不因请求达到 16 次停止后半片 |
| D02 | 逐镜头 | 预先人工标注至少 20 个镜头，含短硬切、叠化和连续长镜头；对可确定硬切，召回率与精确率均 ≥95%、边界误差 ≤2 个来源帧；叠化以区间评估，边界候选/不确定处可修订 |
| D03 | 维度完整 | 十类拆解维度均有独立结果与覆盖状态；无该元素与没分析有明确区分；每条观察有时间证据，没有音效/音乐/运动真实证据却报告已观察的条目为 0 |
| D04 | 文字/声音/动效 | 预标至少 10 个屏幕文字变化、5 个转场/动效、5 个声音事件；关键事件每类至少识别 80%，其余必须显示缺口或待复核；不得用 ASR 输出充当音乐/音效分析 |
| D05 | 跨批一致 | 一段音乐、一个长镜头、一句跨边界台词各跨至少两个窗口；合并后逻辑事件重复数为 0、内容无截断；修改中间批次只重算相邻关系及依赖汇总 |
| D06 | 非口播与长片 | 含无旁白的音乐/文字片、较长多段参考片；无旁白片仍有镜头、文字、动作、声音与节奏结果，不返回空白文案模板代替拆解 |
| D07 | 独立报告 | 不生成新稿/配音即可打开总览、逐镜头表、多轨时间线和制作规则；修订并关闭重开后保留；可导出报告/镜头表与结构化 JSON |
| D08 | 预算和恢复 | 中间批次断开、缺少声音 Provider、预算耗尽分别测；可见待处理轨道/区间，已完成单元不重跑、未知远端请求不自动重发，补齐后继续全片 |

D02/D04 为预标夹具上的待测门槛，不是所有素材质量承诺。场景检测、OCR、真实音频理解和视觉事件理解分别记录误报/漏报，不用全局模型的一段流畅总结替代测量。需要人工修复时保留修复前后结果，不能将人工标注反写为模型原始识别成功。

## 2. 面向用户的完整流程

### 2.1 导入与运行

1. 用户在现有“爆款拆解”入口选择“视频链接 / 本地视频”。本地视频通过桌面文件选择器导入；展示文件名、时长、尺寸、音轨信息和待分析范围。链接保留原有平台识别和登录补救操作。
2. 导入成功后显示可播放的托管副本。源文件移动不影响已导入分析；复制失败时保持在导入步骤，不显示假成功。
3. 用户选择“快速概览 / 整体拆解”。整体拆解展示全片窗口、视听能力和总预算；局部能力缺失具体指出轨道。存在无报价项时写“部分费用未知”，不能显示为 0 元。
4. 运行区固定显示当前阶段、已完成单元数、预算消耗和“暂停 / 继续 / 取消”等可用动作。阶段进度以真实事件更新，等待模型响应时不伪造持续上涨的百分比。
5. 单元失败时保留已完成证据，并展示“重试失败部分”“查看错误”等准确动作；未知远端状态先进入核对状态，不立即重新付费提交。

旧“生成普通生产任务”保留原语义。新增“生成复刻工程”是独立入口，先建立可编辑工程草稿，再由用户选择生成素材与导出，避免把普通任务的立即运行行为意外带入新流程。

### 2.2 查看与修订拆解

结果区采用现有桌面创作工作区模式：左侧为完整镜头/事件列表，中间为原片播放器和视听多轨时间线，右侧为所选事件的证据、参数、解释与修改项。顶部提供“全片总览 / 逐镜头 / 视听时间线 / 制作蓝图”；同一镜头 ID 和时间游标跨视图同步。原有“保存模板 / 生成普通生产任务”仍可到达，新稿/复刻为下游动作。

用户点选一个事件后，中间定位对应源时间、左侧高亮同一事件，右侧显示：

- **看到了什么**：例如字幕从“收藏”切到“用途”，附证据帧和源时间。
- **推测作用**：例如“用反问制造悬念”，标为解释，不能伪装成观众留存的实测结论。
- **对应台词**：有可靠时间戳时可回听；缺时间戳时显示“文字已识别，时间未确认”。
- **可迁移结构**：例如“问题 → 三步处理 → 结果 → 一句行动提示”，允许用户修改。

模型未观察到的音效、动效轨迹或瞬时转场不补成确定事实。深度模式使用帧序列支持的视觉变化描述；没有连续视频或音频证据时，明确写“待确认”。场景变化候选不直接当作语义镜头边界。

用户可修改分段起止、事件作用、台词、素材槽及锚点，合并或拆开区间。保存后产生新修订；重跑分析不会静默覆盖人工修订。合并、重排后选中状态跟随稳定 ID；删除当前事件后选中相邻可用项，不能让检查器继续编辑已删除对象。

### 2.3 写新稿并选择锚点

新稿与原文案分别显示。用户填写主题、目标受众、核心信息与可使用素材，把参考结构迁移到新内容。原片时间作为理解依据，不复制成新片时间。

每段新稿有稳定段落 ID，支持选择“一整段 / 一句话范围 / 某个词出现时”作为画面或音效触发位置。同一短语出现两次时，显示所在段落与上下文，要求精确选定出现位置。修改了被绑定的文字后，相关锚点显示“需重新定位”，不能悄悄绑定到另一处同名短语。

生成配音或导入配音后，分别展示“有时间戳的测量结果 / 人工确认 / 估算”。估算可用于草稿预览；有逐词同步要求的事件必须完成可靠对齐或人工确认后，才能被计入首片同步验收。没有音轨的参考片仍可分析视觉；没有新配音时可以编辑工程，不声称已完成旁白同步。

### 2.4 生成工程与继续编辑

“生成复刻工程”先显示镜头清单：新稿段落、时长、素材槽、动画模板、待解决问题。每个镜头可回看其结构来源，但工程素材必须是用户授权使用的自有或新生成素材；源片证据帧不自动进入成片。

工程中复用导演工作台已有的镜头、字幕、音效、素材版本和审片面板，不增加第二套编辑器。建立工程后，用户可以自由修改字幕、构图和镜头时长。后续蓝图变化通过“查看更新”呈现差异，逐项应用到工程或创建新版本；手工改过的内容必须标出冲突，默认保留。

动画选择首先按镜头功能、素材数量、比例、文案长度及最短时长过滤，再推荐匹配模板。长度超限时提供缩短标题、拆分镜头或更换模板，不静默截断正文。现有 ShotCraft 模板主要按镜头内部时间播放；“选择了逐词纸面压印模板”不等于已经接通任意语音词时点。早期样片先检查整镜切入、字幕跟读与音效；M2 发布前 P09 必须补齐标题/纸卡内部标记及选择性字幕强调，并验证两套渲染路径。其他四模板仍明确为整镜控制。

### 2.5 产生变体与导出

先完成 A 版审片，再从同一已确认蓝图建立 B、C 两个开头。用户看到每版的开头文案、新增素材、需重新对齐的范围、预计新增费用及可复用资产。选择复用依据是依赖指纹和用户锁定情况；不能因为节点同名就认定可复用。

若采用按段生成的旁白且正文输入完全一致，B、C 可复用正文音频、图像和 B-roll。若选择整片旁白重新生成，则必须重做整段语音对齐，不能仍承诺正文音频与时间不变。即使素材复用，开头时长变化也必须重新计算后续全局时间与最终渲染。

导出前显示阻断项和待人工确认项。成片、工程、来源修订以及导出参数一起留档。删除或归档原分析后，已经生成的工程仍能播放、编辑和导出；缺失的源证据只影响回看，不能破坏独立工程素材。

## 3. 状态、错误与降级呈现

| 情况 | 用户可见状态与动作 | 必须满足的行为 |
| --- | --- | --- |
| 链接失效、登录不足、下载失败 | 说明当前阶段与原因；重新登录、重试下载或改用本地文件 | 不将下载失败显示为模型分析失败；不清除已有历史结果 |
| 本地文件被占用、磁盘不足、损坏 | 导入失败；显示修复路径，允许更换文件 | 未完成托管复制前不启动付费分析 |
| 低清、小字不可读、画面遮挡 | 事件标记“证据不足”；可回看、调整区间、人工填写 | 不强制拒绝低清输入，不生成确定的 OCR 内容 |
| 无音轨或音轨静音 | “参考片无可用语音”；继续视觉分析并允许输入台词 | 不伪造逐字稿、词时间或听到的音效 |
| ASR 只有全文无时间戳 | “文字可用，时间未确认”；进入人工对齐或另行对齐 | 不能把 `0,0` 当有效逐词时间；保持 estimated/unavailable 语义 |
| 整体拆解预算将耗尽 | 已有证据可查看；标出未分析轨道/区间，允许增加预算继续 | 16 次是单批初始视觉请求上限，其他批次仍在清单；全片累计费用不重置；部分完成不装成整体已完成 |
| Provider 暂时失败且确认未执行 | 显示失败单元、重试次数与预算余额 | 只重试受影响单元，已持久化成功单元不重跑 |
| 网络断开但远端是否成功未知 | “正在核对远端状态”；显示最后已知进度 | 未核清之前不重复提交可能收费的同一请求 |
| 暂停或取消 | 区分“等待当前请求结束”“正在取消”“已取消” | 停止排队新请求；已在远端执行的请求不能假称立即停止或零费用 |
| 蓝图有未保存更改 | 固定保存提示；切换事件和面板仍保留草稿 | 异步刷新不覆盖输入，恢复任务不抢走正在输入的焦点 |
| 修改台词导致锚点失效 | 受影响事件显示“重新定位”；预览可显示草稿提醒 | 不误绑定到重复短语，不沿用旧配音的逐词位置 |
| 已存在人工工程修改 | 更新差异里显示冲突、保留、应用或另存 | 不后台覆盖用户镜头、素材选择和字幕 |
| 模板不支持比例、数量或时长 | 在创建镜头前说明约束并给出可用替代项 | 不导出裁掉主体、读不完或缺必要素材的画面 |
| 后期 Hypit 不可用或无分发授权 | 隐藏/禁用后端执行并给出设置原因 | StoryDream 原生链路仍可完成首片；不能把启动子进程当作许可解决方案 |

## 4. 首条 26 秒样片与三个开头

以下是可使用自制素材制作的验收剧本，不是本轮已经分析过的真实视频。主题为“把收藏变成能使用的知识卡片”，避免依赖第三方商品、真人形象或未经核实的效果数据。先自行制作一条同结构参考片并人工标注源时间，后续以它作为可重复测试夹具；另补真实授权参考片检验泛化。

### 4.1 A 版目标分镜

| 新片计划时间 | 旁白 | 视觉与可选模板 | 验收点 |
| --- | --- | --- | --- |
| 0.0–4.0 s | 资料越存越多，为什么下次还是找不到？ | 纸面问题标题；`shotcraft-paper-title`，不传图片槽 | 标题完整可读；问题词与字幕强调一致 |
| 4.0–9.0 s | 先记下它能回答什么问题，再保留原始出处。 | 一张卡片写入“问题 / 出处”；`shotcraft-paper-tape` | 在“问题”对应语义位置切入卡片；出处是自制示例，不伪装成事实引文 |
| 9.0–14.5 s | 把关键信息分成三个要点，做成一张卡片。 | 三张短标签依次展开；`shotcraft-paper-popup` | 项目数为 3，标题长度符合模板限制；整段动画有足够阅读停留 |
| 14.5–21.0 s | 写方案时，按问题把卡片找回来，原文也能一起核对。 | 三条来源汇入“方案”；`shotcraft-source-merge` | “找回来”附近进入汇聚镜头；素材关系正确，无额外模型素材请求 |
| 21.0–26.0 s | 今天先试一篇：存之前，多写一句用途。 | 一张简洁行动提示卡 | 结尾完整、旁白无截断、最终画面可读停留至少 1 秒 |

上述区间是拍摄/配音规划值。实际旁白测量后重新求解镜头边界；若偏离 20–30 秒范围，应调整文案或节奏，不能为保留表格时间而硬截音频。语义锚点至少包含“问题”“三个要点”“找回来”“一句用途”，每个锚点有唯一段落上下文。

首个稳定样片优先使用本地自制纸张、图标、卡片及已有可用配音文件验证工程闭环，再用配置的模型渠道做一次真实生成验收。这样能分别识别桥接错误和生成质量问题；使用付费渠道的实测记录包括模型、输入摘要、调用次数、耗时、费用来源与产物版本，不写入凭据。

### 4.2 A/B/C 开头变体

| 版本 | 开头文字 | 结构差异 | 预期重做范围 |
| --- | --- | --- | --- |
| A：问题式 | 资料越存越多，为什么下次还是找不到？ | 先提出痛点 | 基准版本 |
| B：行动式 | 别急着收藏，先给这份资料一个下次用途。 | 先给出一个动作 | 开头文案、开头旁白及其对齐、开头标题图层；全片时间求解和渲染 |
| C：结果式 | 我把一堆收藏，整理成了能直接使用的卡片。 | 先展示结果 | 开头文案、开头旁白及其对齐、开头视觉；全片时间求解和渲染 |

正文 4 段和所用素材均保持相同输入，以测试真正的复用。B、C 开头时长不要求与 A 一致：假设 A 为 4.0 秒、B 为 4.4 秒、C 为 4.8 秒，在正文 22 秒不变时全长分别为 26.0、26.4、26.8 秒。这是说明时间传播的样例，最终数值来自实测旁白。正文的局部词时间与素材版本应相同，全局起点随开头变化。

增加两次针对性编辑：把 B 的“下次用途”改成重复出现的短语，验证旧锚点明确失效；在 C 工程里手工移动结尾字幕，再更新蓝图，验证差异预览保留手工修改。两次编辑均不触发不相关正文图像重新生成。

## 5. 可量化的验收门槛

| 编号 | 检查项目 | 通过标准 |
| --- | --- | --- |
| A01 | 首片完成度 | A 版在原生导演工作台可编辑并导出 20–30 秒 MP4；包含可编辑文案、镜头、字幕和素材引用，无阻断审片项 |
| A02 | 时间证据 | 人工夹具至少 12 个已标注事件；所有已输出“观察”事件都有有效源区间及证据引用，越界引用为 0；点击回放定位误差不超过 200 ms |
| A03 | 深度采样价值 | 夹具含 3 个等距 8 帧易遗漏的短事件，预先固定位置与人工标注；深度模式至少命中其中 2 个，且可回看证明；记录快速/深度差异，不能临时挑成功片段 |
| A04 | 观察真实性 | 首片全部观察项人工核对；无证据的音效、运动或因果断言为 0；推断可以保留，但必须与观察分开显示 |
| A05 | 中文语音同步 | 三个版本合计至少 12 个人工标注关键锚点；具备可靠对齐或人工确认后，事件相对人工语音基准的绝对误差中位数 ≤120 ms、最大 ≤250 ms；estimated 结果不计为通过 |
| A06 | 时间传播 | B、C 开头变长后，所有正文全局时间同步平移，无负时长、越界字幕或旁白截断；量化到输出帧率的偏差最多 1 帧 |
| A07 | 变体复用 | 在正文按段生成且输入不变的测试条件下，正文素材和正文配音版本复用率为 100%，正文图像与配音 Provider 新请求数为 0；开头有变化的依赖必须失效 |
| A08 | 恢复与重复费用 | 在抽帧、视觉单元完成、生成请求已提交、保存工程四处注入中断；恢复后已持久化成功单元重复执行数为 0，状态未知请求的自动重复提交数为 0 |
| A09 | 预算 | 快速分析证据帧不超过 40；整体拆解每批帧/引用 ≤64、单元 ≤16、初始视觉调用 ≤16，完整任务按批次数及视频/音频用量汇总；自动付费重发 0；显式重试不清空累计额度，未知费率不计为免费 |
| A10 | 编辑持久性 | 蓝图修改后刷新/重启可恢复；旧运行迟到事件不能改写当前稿；从蓝图更新工程时人工冲突被展示并保留，静默覆盖次数为 0 |
| A11 | 独立工程 | 删除测试分析记录及其托管证据后，已生成 A/B/C 工程仍可预览和导出；归档记录仍可回看其证据，前提是托管文件未删除 |
| A12 | 输出媒体 | `ffprobe` 核对尺寸、帧率、时长、音视频流；1080×1920 / 24 fps 首片通过；时长相对计划成片尾点误差 ≤2 帧，尾音完整，无黑帧闪烁和字幕裁切 |
| A13 | UI 可用性 | 1440×900 与 1100×760、深浅主题共 4 组核心路径通过；窗口拖动到紧凑尺寸仍能完成选证据、改稿、生成工程、导出，不需要横向滚动整个页面 |
| A14 | 分发独立性 | 新安装环境未安装 Hypit 时完整完成首期流程；产品包和核心依赖中不包含未授权的 Hypit 实现；可选适配器关闭不影响旧报告与普通任务 |

UI 回放的 seek 误差、语音锚点识别误差和渲染帧量化误差是不同指标，必须分别记录。A05 为首个闭环门槛，不表示所有中文场景已达该精度；推广前应覆盖数字、英文名、多音字、重复短语、快慢语速和停顿。

首片同时记录冷启动/热运行耗时、峰值内存、各阶段模型调用、用户实际修订次数和人工复核时间。首轮先建立可复现基线，不承诺固定秒级处理速度或固定单片成本。出现质量换取速度的降级必须写进报告。

## 6. 实现后的测试与 QA 清单

### 6.1 自动测试

- 契约与时间：秒/毫秒转换、原片/新片/镜头局部时间、重复短语、缺失词时间、0 值时间、中文标点、拆分合并后稳定 ID、段落删除与锚点失效。
- 分析编排：相同证据帧去重、快切候选与语义区间区别、逐单元 checkpoint、费用预算含重试、暂停取消与恢复、无音轨与坏文件降级。
- 持久化与并发：旧结果加载、人工修订保存冲突、迟到运行结果、磁盘写入失败、复制中断、重启后托管文件与工程引用完整性。
- 工程与资产：独立素材快照、增量更新差异、手工编辑保护、素材 pin 与输入变化、整片配音/分段配音的复用区别、比例与模板限额检查。
- 真实链路：Electron 文件选择、链接下载接点、媒体协议播放、工程建立、保存重开、真实导出；浏览器预览对桌面专属动作显示明确不可用，不能模拟已经导入成功。

测试优先验证上述业务不变量，不为每个字段机械写镜像测试。实现后运行受影响的现有与新增测试及 `npm run typecheck`；共享 UI、主进程或工程格式变更后运行 `npm run build`。沿用现有 `qa:editorial`、ShotCraft 渲染 QA 和音画同步 QA 的能力，增加复刻流程专用夹具；现有脚本通过不能代替新流程验收。

### 6.2 视觉与交互 QA

所有新控件从 `src/ui` 复用；颜色、文字、边界、焦点和状态使用 `src/styles/tokens.css` 的语义 token。图标沿用 Lucide，不直接在业务页引入 Fluent 控件或新增裸表单控件。历史页面残留裸控件在修改到的流程内逐步迁移，不借此重做无关页面。

| 场景 | 必查项 |
| --- | --- |
| 正常/紧凑桌面，深/浅主题 | 列表、播放器、检查器层级稳定；狭窄时侧栏可收起，选中和草稿不丢；文本、禁用和警告有足够辨识度 |
| 空白、导入中、分析中、部分完成、失败、完成 | 主操作位置稳定；加载不挤走输入和工具栏；状态文案说明下一步可做什么 |
| 选中与快速切换 | 事件列表、回放时间和检查器一致；异步返回旧事件不污染当前项；鼠标选择不抢正在输入的焦点 |
| 键盘与焦点 | Tab 顺序清楚；图标按钮有名称；面板切换/关闭后焦点恢复；未保存更改和错误可被键盘用户发现 |
| 滚动与定位 | 每个 Pane 负责自己的滚动；定位事件只滚动最近容器；工具栏与播放器不随长检查器内容意外移走 |
| 文案极值 | 长文件名、长中文标题、数字夹英文、空转写、大量失败信息；不裁掉关键动作，无全页横向溢出 |
| 配音与预览 | 连续播放、拖动、暂停恢复、快速切镜头时没有重复叠音；视频 seek 完成前不把旧帧当成新证据 |
| 工程冲突与变体 | A/B/C 标签清楚，差异与需重做范围可理解；批量操作不会误改未选中版本；手工冲突默认保留 |

为每组主题/尺寸保留导入、证据选中、锚点失效、更新冲突、导出完成的截图，以及一个关键流程录屏。逐张检查截图，不能仅依据源码或 DOM 尺寸宣称视觉通过。输出视频至少抽查首帧、每个镜头切换前后、语义事件前后、长字幕与最后 1 秒，并完整听看一次 A/B/C。

### 6.3 测试交付物与通过顺序

测试产物集中保存于后续运行生成的 QA 目录，至少包括：输入夹具与 SHA-256、人工源事件/语音标注、蓝图修订、工程快照、模型调用收据、复用/失效报告、错误恢复日志、四组 UI 截图、三条导出视频及 `ffprobe` 结果。目录中的密钥和登录 Cookie 数量必须为 0。

按顺序验收：先用确定性本地夹具通过时间与恢复测试，再完成 A 版真实编辑导出，再产出 B/C 并验证复用，最后跑四组 UI QA 与补充比例/帧率回归。只有在这条主链路通过后才扩大视频种类与变体数量；Hypit 后端另设兼容、取消、Worker 恢复、许可证和 Windows 安装验收，不作为首片的替代路径。
