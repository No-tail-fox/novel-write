# 差分更新落地与发布说明

状态日期：2026-10-30。差分服务端和管理网站已完成生产部署及外网验证；完整私有备份保存在服务器。1.0.3 安装包已通过隔离环境中的真实升级、两次启动、账户和授权保留验收，原安装及注册信息已还原。桌面生产版仍为 1.0.2：当前 SSH 在协议握手前断开，尚未上传或发布 1.0.3。既有生产授权、设备绑定、CA 和签名密钥保持不变。

## 实现范围

- 使用固定版本的 electron-updater 6.8.11 差分重建引擎，以及 builder-util-runtime 9.7.0；不另写一套补丁算法。
- 下载时复用本机缓存的当前版本安装包，仅请求新版本缺少的字节区间；重建完整安装包后验证 SHA-512、SHA-256 和大小。
- 网络适配器只访问配置的 HTTPS 源与指定安装包路径，使用现有私有 CA；不跟随重定向、不接受非 206 分段响应。
- 差分清单单独使用 Ed25519 签名，绑定版本、发布序号、文件名、大小及哈希，有效期不超过 24 小时。v1 更新清单字段不变，旧客户端的严格校验不受影响。
- 缓存缺失或损坏、索引缺失或篡改、签名无效、服务器不支持 Range、重建哈希失败时，回到原有全量下载。已有 .part 文件继续断点续传，不先做差分。
- 安装仍需用户确认和关闭软件；保留安装前再次检查发布版本、校验安装包、运行中任务保护、授权限制与防降级机制。这不是运行中热替换 app.asar，也不是跳过完整安装。

## 管理员如何发布

线上后台已支持以下流程；发布仍须先完成候选安装包验收。

1. 递增 package.json 与 package-lock.json 中的桌面版本。保留生产 CA、签名公钥配置，构建并验证 Windows x64 安装包。
2. 同一次 electron-builder 打包生成 `StoryDream-Setup-<版本>.exe` 和同名 `.exe.blockmap`。NSIS 已明确开启 differentialPackage，打包脚本检查两者均存在且非空。
3. 网站“版本更新”中选择安装包，再选择同一次打包的“差分索引”，填写版本、最低版本、更新说明并确认发布。索引可选，不选仍是原有全量发布。
4. 版本发布会照常自动生成更新公告；不需要另发一份差分公告。客户端依旧在启动、每小时及打开公告入口时拉取，未改成长连接推送。
5. 不要单独替换已发布安装包或索引。发布错误时撤回版本并发更高版本；撤回同时停止该版本安装包、索引、差分清单和更新公告的访问。

CLI 同样支持可选索引参数：

```bash
storydream-license publish --file /private/StoryDream-Setup-1.0.3.exe --blockmap /private/StoryDream-Setup-1.0.3.exe.blockmap --version 1.0.3 --minimum-version 0.0.0 --notes '版本更新说明'
```

上述路径与版本是发布示例，不代表已上传或已发布。仍须上传完整安装包，blockmap 只是索引；客户端减少的是下载流量，服务器无需为每对版本生成补丁包。

## 推荐上线顺序

1. 在维护窗口备份现有服务代码、完整私有状态和密钥，再升级服务端。新增 release_differentials 表，不重新初始化生产身份或数据库。
2. 用既有客户端验证授权、公告、v1 更新发现和全量下载；单独验证新接口、精确 Range、撤回行为。服务器升级本身不会改变已安装客户端。
3. 先完成隔离 TLS 差分测试、Windows 独立用户配置中的候选 NSIS 真实升级、重启和授权保留验证。不要为测试把候选版本发布到生产；本轮 Windows 隔离安装验收已通过，尚未执行发布后软件内下载及点击安装的全链路验收。
4. 验收通过后，正式发布包含差分能力的下一版客户端及匹配 blockmap，例如 1.0.3。旧版 1.0.2 仍全量下载这次升级。
5. 后续如 1.0.3 到 1.0.4，只有客户端保留了 1.0.3 的下载缓存，且服务端仍保留可用的对应索引和清单时，才可复用。手动安装、清空缓存、旧版本无索引或被撤回时会全量下载。

差分成功率和节省比例取决于两次安装包实际差异、压缩布局及缓存情况，不保证固定比例。本地仍需空间保存基准包和重建后的完整新包；差分中断不会保留分块续传，原有全量 .part 续传仍可用。
