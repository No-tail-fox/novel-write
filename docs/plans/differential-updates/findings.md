# Findings

- Existing v1 release schemas are strict. Differential metadata must use a separate endpoint.
- Existing trust chain uses a private CA, Ed25519 release signatures and SHA-256 installers.
- Current full downloads support resume; retain this path as fallback.
- Server uses randomized artifact filenames, so previous blockmaps cannot be inferred by version.
- Use upstream block-level reconstruction, not live replacement of app.asar.
- Preserve existing working-tree edits and production signing keys/state.
- Runtime dependencies are pinned to electron-updater 6.8.11 and builder-util-runtime 9.7.0; only the adapter imports the upstream internal downloader.
- Real blockmaps generated by the installed electron-builder 26.15.3 work with the pinned downloader. The eight-block test downloads one changed 32 KiB block and reuses seven blocks (87.5% of installer bytes).
- A synthetic SHA-256 blockmap must not be mixed with real builder Blake2 checksums in a corruption fixture: that causes full network transfer instead of incorrect reuse. The tampered-map test now deliberately copies the real old map.
- Invalid range responses must destroy the ClientRequest with an error. Destroying the response first suppressed the request error and hung fallback; regression coverage now exercises a server returning 200 to a Range request.
- Existing full-download .part files take precedence, so previously downloaded bytes are not discarded for a differential attempt.
- C: disk space is too low for upload-test reserve checks. Tests use I:/opc/tmp; reserve checks remain intact.
- Server/admin deployment and 1.0.3 packaging completed. Publication remains gated on real 1.0.2-to-1.0.3 installation acceptance.
- Isolated upgrade initially failed inside the old NSIS uninstaller while moving d3dcompiler_47.dll. Restart Manager found no owner. Both x86 and x64 PowerShell moves succeed; current standalone NSIS MoveFileW and Rename/restore probes also succeed. This does not yet establish the original failure's cause.
- Acceptance now records the NSIS rename/restore probe immediately after closing the baseline app. Candidate bytes, production identity, source installation and user profile remain unchanged.
