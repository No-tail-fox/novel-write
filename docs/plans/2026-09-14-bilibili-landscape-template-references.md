# B站横屏草稿模板：真实画面参考

调研日期：2026-09-14。目标是为 StoryDream 增加真正按 16:9 构图的草稿模板，减少常驻文字遮挡主体。本文记录用于排版判断的公开作品，不构成平台热门排行或受欢迎程度统计。

## 获取方式与证据范围

已加载 `web-access` 与 `agent-reach` 技能。`agent-reach doctor --json` 确认本环境的 B站可用后端为“B站搜索 API”；没有安装 `bili-cli` / OpenCLI。`web-access` 前置检查发现没有浏览器调试连接，因此沿技能允许的公开 API 路径读取，不使用账号登录态，也没有操作用户已有浏览器标签页。

来源链：B站匿名首页请求 → 搜索接口 `/x/web-interface/search/all/v2` → 作品详情 `/x/web-interface/view` → 平台播放进度预览接口 `/x/player/videoshot` → 接口返回的公开缩略图雪碧图。每个入选作品都通过详情的 `dimension` 验证为 16:9，再实际查看平台预览画面。不是仅凭标题或封面推测内容。

这里观察的是平台提供的 480×270 播放进度预览帧，不是浏览器连续播放录像。没有声称完整看完作品。预览图时间索引可能为离散采样近似值；本文用“约”标示。低分辨率预览足以判断大体构图与字幕位置，不用于精确测量原片字体字号。

本地总览：[封面和播放预览对照图](../../tmp/bilibili-template-research/bilibili-landscape-reference-contact-sheet.jpg)。左列为封面，其余三列为播放预览帧。原始元数据、预览 API JSON、原图与分帧均保存在 `tmp/bilibili-template-research/`；`reference-manifest.json` 保存作品、日期、比例和帧索引映射。参考图只作开发调研材料，不作为应用模板素材分发。

## 画面观察及设计含义

| 参考 | 实际可见的画面结构 | 用于模板的判断 |
| --- | --- | --- |
| 何同学评测 | 口播时人物位于画面中部，单行白色字幕靠下；切入产品时以产品特写为主，局部参数和数字贴近对应对象；部分相机或跑分比较镜头使用左右对照。橙色超大“iPhone17”是封面排版，不是所有播放帧的常驻标题。 | 横屏数码模板可留一个小章节标签、主体大画面和底部字幕；比较或参数是局部重点，不应叠加整段说明。 |
| 毕导图解 | 口播可在右侧放一块解释图；公式画面大量采用黑底，演示对象与彩色公式左右分区，白色对白字幕单列落在底边。口播画面与全屏图解会切换。 | 可做“左右图解”模板，以约 30% / 70% 分配短标题区和图像区；最多两行重点文字，正文交给字幕。公式不应被标题覆盖。 |
| 一席演讲 | 人物中景周围保留大面积深色空间，白色字幕置底；舞台远景才同时展示讲者与上方投影。封面上的左右巨字在多数人物近景中消失。 | 可做“人物讲述”模板：人物或主图充分占据横屏，标题只在边角短小呈现，底部对白保留独立通道。不要把封面的字数复制到正文画面。 |
| 影视飓风探访 | 双人、多人和空间环境同时构成宽幅主体，字幕位于下方；部分镜头有两行中英字幕；部分镜头有小地图或示意叠图。没有全程固定的大标题条。 | 可做“宽屏纪实”模板：主图满幅或大幅展示，降低固定装饰，字幕不与常驻大段说明同区。素材适应优先保留横向环境。 |

## 建议的实现参数

下面是基于上述观察形成的应用设计值，**不是 B站官方安全区规范，也不是原片的精确像素测量**。

- 所有新增模板明确标为“横屏 · 16:9”，建议画布为 1920×1080；缩略图本身也按 16:9 展示，避免只改名称却沿用竖屏布局。
- 主体区优先给足横向宽度。全景、人物模板可占 85% 以上画幅；图解模板才使用左右结构，且标题区和图片区之间应有可见间隔。
- 以 1920×1080 为参考，普通对白字幕约 34–42 px，最多两行，置于画面高度约 86%–94% 区域；左右留约 5%–8% 内边距。字号应受字幕行长约束，不把横屏宽度直接填满成超长句。
- 短标题约 44–64 px；小章节标签约 22–28 px。只保留一种标题层级，不同时开启标题、摘要、分镜文本和字幕四套常驻文字。
- 人物和纪实模板把正文留给字幕；知识图解模板的旁栏只放本段短标题或一条要点。不要把整段旁白复制到旁栏再叠加字幕。
- 录屏教程、信息图采用 `contain` 或等效完整显示行为，确保素材边缘、软件菜单和数据标签不被裁掉；人物全景可使用适合其素材的填充策略。
- 如模板系统暂不支持“仅片头出现标题”，优先默认关闭常驻主标题，保留用户可手动开启的短章节标题，比一直遮挡主体更符合所见样本。

建议新增方向：宽屏纪实、人物讲述、左右图解、横屏评测、录屏教程。最终名称和数量可按现有系统能稳定表达的排版能力调整。
