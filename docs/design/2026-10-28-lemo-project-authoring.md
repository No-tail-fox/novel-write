# Lemo 连续影片的分步创作与恢复执行

日期：2026-10-28。

## 目标与边界

保持 Lemo 的连续影片：一部影片只组装一个 HTML 页面、一套绘图资源和一个 `window.render(t)`。t 始终为全片绝对秒数。镜头是编辑与抽帧检查的时间窗口；创作单元的拆分不产生独立短片，也不引入片段首尾动画重置。

本次只修改创作与执行能力，不迁移或重跑现有项目，不访问正式数据库，不调用付费生成接口。

上游参考固定在 3961ddb3d24d8876e0e2754f7790d66908acee51，导演方案使用 DIRECTOR.md、TECHNIQUE.md 和选定 STYLE.md 的完整资料；增量编辑阶段保留完整 TECHNIQUE.md 与选定 STYLE.md，导演意图由已保存方案传递。资料中的工具、终端命令和示例交付格式是参考数据；宿主使用自己的接口和文件契约。

## 创作工程

LemoNativeFilm 增加可选 project.version = 2。源码单元保存在项目文档中，由既有存储和步骤回执持久化：

- shared：创建全片画布、笔触、缓存、图片等公共资源，返回绘图 API 与可选 ready。
- scene-N：每组最多八个可编辑镜头窗口，返回 render(absoluteSeconds)、texts(absoluteSeconds) 和可选 ready。时间仍为全片时间。
- director：编排连续场景、转场与文字元数据，并确定性地合成任意一帧。

每个单元都是 async 工厂函数的函数体，参数为 input、shared、scenes、core、THREE，以显式 return { ... } 结束。宿主按依赖顺序执行并等待每个 ready，再发布一次 window.render / TEXTS / DUR / READY。文案、字幕时刻、画布规格、素材绑定由宿主提供，不让模型重新转录。

单文件源码上限 90,000 字符，全片源码上限 420,000 字符，每文件保留最近十二次尝试，包括源码、步骤请求 ID、供应商请求 ID、结束原因、用量和诊断。最大支持五百个镜头窗口。

## 执行顺序

1. 导演方案：完整文案、选定风格、公共资源、场景安排和素材清单。
2. 素材门禁：检查生图开关、已导入文件、纪实资料的出处与许可。
3. 按素材分别准备：每项有独立步骤和回执，生成插画与本地资料形成素材 ID 绑定。
4. 配音与精确排时：沿用现有音频管线。
5. 公共绘图代码、首个连续场景。
6. 样片浏览器检查；只修复相关文件，复查通过后才创作后续场景。
7. 剩余场景、整片调度文件。
8. 整片浏览器抽帧；按诊断修复相关文件，复查仍失败则保留工程并停止。
9. 镜头窗口编译、连续影片渲染与媒体检查。

样片由公共资源和首个可编辑场景临时组装；尚未完成的其他场景和调度文件不会阻止样片检查。锁定窗口保持原有内容。

## 素材与来源

导演方案的 materials 清单最多二十四项：

- generated：生成插画，必须启用生图。素材准备与代码创作独立，不强制给每个镜头插入图层。
- existing：绑定实际导入且可读取的本地图片。
- evidence：绑定本地图片，并要求设置中填写资料出处与许可；已知由 text-to-image 生成的素材不能充当纪实证据。

Edit & Documentary 分类要求真实 evidence。纯代码绘图允许空素材清单。文件读取时计算 SHA-256，正式播放器接收素材 data URL。

方案完成后动态加入素材节点，并执行供应商预检和容量预留；退出执行时释放预留。新方案未复用时先清掉旧清单的任务结构，避免预留旧素材任务。

## 恢复与重试

服务先持久化步骤运行声明和请求 ID，再执行供应商调用，随后保存结果回执和文档。素材及各源码文件独立留存。

增量模式下，模型达到长度上限、返回坏格式或产生无效代码时，保存本批原始回复和用量，保留上一批可用源码，并标为明确失败。恢复时只重做该批及其受影响的下游。旧的完整文件创作仍保留不完整源码及用量；已成功素材和前序文件可复用。

网络断开等结果不明的付费请求仍标为 unknown，不能自动重复提交。先读取已保存回执或供应商记录；无法核对时沿用现有人工恢复选项。失败的复查回执还恢复其关联文件的修复状态，防止重启后漏掉需要重做的文件。

输入哈希排除自身输出、后续复查诊断和修复源码，避免一次修复使先前付费成功步骤失效。文案、视觉设置、字幕选择、镜头集合和素材计划变化会通过输入哈希与依赖关系使相关步骤失效。

## 增量编辑事务

新建工程按「建立小型可运行基础 → 多批补充绘图与编排 → 样片/全片复查」创作。文件拆分继续只表示创作范围，影片仍只有一个时钟。

- 每个付费批次是一个 film-edit 节点，先保存请求声明，单次调用模型，再写回执和工程。批次之间可暂停；每个文件每个阶段最多 16 批，达到上限后在不收费的文件检查节点停止。
- 模型返回 JSON：baseHash、edits（唯一精确查找/替换）、done、summary。baseHash 必须匹配保存源码的 SHA-256；首次空文件允许一次插入。其后按顺序应用最多 12 处修改，查找与替换合计最多 24,000 字符，每处替换最多 16,000 字符。提示词要求每批新增代码约 6,000 字符。
- 整批修改先在内存中完成，全部通过版本、唯一位置、大小及完整工厂语法检查后才提交。无效修改不会覆盖已通过检查的源码。done=false 自动展开下一个持久化节点；done=true 才能通过文件检查。最近十二次尝试保留批次 ID、原始回复、是否应用和修改摘要；独立步骤回执继续保存各次结果。
- 初次创作、样片修复、全片修复各有独立会话，以稳定父节点 ID 标识。复查仍失败时保留源码，并将目标修复会话重新打开，下一次继续新批次。诊断及后续源码变化不使历史成功批次失效。
- shared 只收到公共视觉设置、素材说明与粗时间窗口；scene 只收到所属镜头的精确字幕排时和共享 API；director 只收到场景接口及时间窗口。避免每次复制全片文案和所有字幕 token。实际组装时仍注入完整宿主时间线。

## 导演方案输出预算（兼容旧任务）

完整导演方案不再使用通用短 JSON 的 4096-token 默认值。lemoPlanRequest 为该阶段提供 65536-token 的 defaultMaxTokens 和 600000ms 超时；这只是最大输出许可，不是固定用量，也不保证所有模型或中转渠道都接受该上限。该预算与现有分批代码创作预算保持一致，为推理和完整方案正文留出空间，未修改文稿、风格资料、模型或素材策略。

共享 JSON / 文本适配器按协议映射预算：Anthropic Messages 和现有 Chat 路径使用 max_tokens，Responses 使用 max_output_tokens。显式配置优先于阶段默认值；Chat 的 max_completion_tokens 不会被额外添加的 max_tokens 覆盖或冲突。Anthropic JSON 转入流式文本路径时必须继续传递该默认值。未指定阶段预算的其他 JSON 任务维持既有行为。

输出预算与工具能力是两个独立问题：不强制工具能避免相应 HTTP 400，但 HTTP 200 不代表方案完整。max_tokens 截断仍保存原始回执并明确失败；不补造 JSON、不悄悄压缩用户文案、不追加收费续写或自动换模型。用户显式设置较低上限或渠道施加更低限制时，仍可能需要调整预算后人工重试。只有真实完整方案通过校验，才可认定该步骤通过；单元测试和旧回执重放均不代表视频全流程成功。

## 流式接收与持久化边界

代码请求启用 SSE，支持 OpenAI Chat、Anthropic Messages 与 Responses。保留模型文本、供应商请求 ID、结束原因和可用的用量。接收按 UTF-8 与事件边界解析，沿用总超时和 8 MiB 响应上限，流式请求只尝试一次；供应商返回普通 JSON 时沿用完整响应解析。

收到结束事件后的尾部断链可使用已经完整收到的结果；超出响应上限仍失败。未收到完整结束事件的断链保留已接收文本并标记 unknown，不能当作已完成代码或直接自动续费。长度上限导致的明确结束属于已知失败。

持久化单位是批次结果与回执。SSE 分块在请求进行中仍处于内存；进程被强杀时不保证保留该请求的最后几个分块。前序已保存批次不受影响，当前付费请求按 unknown 恢复。没有实现视频渲染片段缓存或从某帧续渲染。

## 兼容

runtime 提供 authorFilmFile 或 editFilmFile 时创建 authoringVersion = 2。仅新导演方案在具备 editFilmFile 时写入 project.authoringMode = incremental。既有 version 2 工程未标记此模式时继续完整文件创作；旧的原生全片任务和传统模板任务沿用旧图。已成功的旧版导演方案继续复用，不因升级额外收费。旧版第一步明确失败且未完成、云端结果已知的任务，在用户继续时迁移到分阶段规划；结果未知的任务不会自动迁移或重发。

## 验证与限制

针对性测试还覆盖版本冲突和歧义修改拒绝、逐批回执先于下一次请求保存、第二批失败保留首批源码、暂停及重启只继续未完成批次、回执成功而文档保存失败后的恢复、最大批次限额和修复会话继续执行。原有测试覆盖截断源码和元数据保存、样片门禁、定向修复、进程重启后的失败回执恢复、结果不明禁止重发、素材门禁和复用、动态容量预留、重规划、锁定窗口及五百窗口的有界依赖图。

离线 Electron QA 使用正式制作设置及进度组件，在 1536×1024 与 1040×720 两种窗口、深浅主题下检查保存、重试、恢复、禁用状态和裁切。另一组浏览器夹具使用正式组装器、编译器、素材就绪流程和播放器，检查样片与全片、素材实际绘制、跨窗口绝对时间偏移及非顺序重复跳帧。

这些验证均隔离正式数据库并禁止外部网络请求。真实供应商输出质量、长片创作成本和完整付费渲染链路尚未通过实单验证。替换相同路径的本地文件时应重新准备素材；当前导入素材的规划哈希使用 ID、名称与路径。


## 检查点式分阶段规划（2026-10-29）

原来的第一步一次要求完整逐秒导演方案，4096-token 通用预算可能在推理与正文生成期间耗尽。HTTP 200 只表示请求返回，不能表示完整方案通过。提高预算只是兼容措施；新任务由生产 runtime 显式开启 planningVersion=1，将规划工作拆入现有持久化 DAG，而非另建通用 Agent 循环。

顺序为：全局创意大纲（plan）→ 影片素材清单（film-plan-materials）→ 每组最多 8 个镜头的导演规划（film-plan-scene）→ 本地完整性校验（film-plan-finalize）→ 原素材、旁白、分批代码、样片、全片与渲染检查。前三级每个节点最多一次模型调用，最后的规划汇总不收费。仍使用项目配置的模型和协议，不替换用户文稿、风格或素材策略。

- 大纲只返回整体视觉与叙事原则以及帧率：正文 40–4000 字符，默认输出预算 65536 tokens。不再要求同时生成逐秒分镜、素材与代码。
- 素材清单最多 24 项；每项用途不超过 500 字符，生图提示不超过 1200 字符，默认输出预算 65536 tokens。继续校验生图开关、实际导入文件、证据出处与许可，不能把生成图片冒充证据。
- 每段只接收相关原始镜头窗口、全局大纲、素材概要及原风格参考；不重复输入全文。每镜头方向 20–700 字符，段摘要 10–600 字符，默认输出预算 65536 tokens。必须原序、完整且无重复地覆盖指定镜头，只能引用已规划素材。
- 默认预算仍服从用户显式参数；输出结束原因为 max_tokens/length 时仍明确失败，即使返回前缀恰为合法 JSON。不会截掉内容、修补 JSON 或自动续费重发。
- project.planning 保存版本、大纲、冻结的镜头组、素材完成标记、各段方案及总完成标记。中间状态为 planning；本地校验每个镜头与素材引用后才改为 planned。任何未完成规划都禁止制作；界面也不在此时显示无可检查源码的代码复查入口。
- 下游共享代码和整片调度收到各段摘要；场景创作只收到相关方向。配音校时不会使已付费规划失效，自动拆镜后使用原镜头方向；若已拆镜工程重新规划，则优先使用本轮直接分配的镜头 ID。
- 检查点和请求声明沿用原 service。分段失败只重试失效段，保留之前完成的节点与回执；源文稿、风格等实际输入改变时重新规划。明确 HTTP 拒绝与网络中断的未知结果继续区分。未知请求不因恢复、迁移或展开任务而自动重发。

新流程的三协议依然由配置明确选择：OpenAI Chat、OpenAI Responses、Anthropic Messages。规划请求通过对应适配器映射输出预算，Anthropic 使用文本 JSON SSE 而非强制工具。不能把自动选择协议与自动把一个收费请求发往三个端点混为一谈。

## 输出预算放宽与显式配置优先（2026-10-29）

大纲、素材、分段导演规划以及原生代码创作/修复统一采用 65536-token 默认输出许可；这不是要求每次生成这么多内容，也不是整部影片的累计上限。分阶段与较宽预算同时保留，不通过缩减用户文稿来规避截断。

代码生成改用 defaultMaxTokens，而不再通过 maxTokens 强行覆盖模型请求配置。原生代码请求统一使用现有流式接收器，旧全片代码入口也不再遗留非流式调用。用户明确配置的输出参数优先，既可低于默认值，也可高于默认值；三种协议继续按各自支持的字段传递。131072 的回归仅证明配置不会被客户端压回 65536，不代表当前中转渠道或所有模型支持该数值。模型/渠道的真实最大输出能力仍是外部约束，不能靠删除客户端参数获得无限输出。

本轮不修改短 JSON 任务的通用默认值，不自动切换模型、不试探付费端点、不在截断后偷偷重买请求。截断保留原始回执并失败，已完成阶段保持可复用。验证使用 mock 网络的真实适配器调用和生产入口共享参数；不代表真实模型视频全流程验收。
