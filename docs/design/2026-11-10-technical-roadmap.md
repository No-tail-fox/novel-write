本文是三条制作路线的**总纲**：定位、技术链路、共用底座、下一步怎么走、怎么验收。细节分别见：

- [2026-11-09-lemo-faithful-mode.md](2026-11-09-lemo-faithful-mode.md)：Lemo 贴近上游模式
- [2026-11-10-route-split-and-upstream-render.md](2026-11-10-route-split-and-upstream-render.md)：路线拆分、上游出片、真实模型实跑记录

## 0. 结论

1. **产品上固定三条路线，各管一类需求，互不替代。**
   - **创意动画 = Lemo**：导演型 Agent 写整片代码，追求独特画面。
   - **模板动画 = Remotion 模板**：AI 只做内容和素材，画面由已适配的模板保证，追求稳定、可批量。
   - **HTML 动画 = 按场景生成 HTML**：介于两者之间，适合图文解说。
2. **技术上用一个底座托住三条路线。**三条路线共用：
   - 存储；
   - 模型网关；
   - 配音与时间线；
   - 编码；
   - 校验闸门。

   差异只留在「谁来写画面」这一层。Lemo 的成片例外：按上游原样，用 `video.mjs` 出画面、用 `mux.sh` 混流，底座只负责托管和复检。
3. **下一阶段先做稳定性，不扩功能。**今天的实跑说明，出片质量已经可用，失败几乎都来自外部服务：
   - 模型不可用（404/503）；
   - 中转站 524；
   - 配音断线（ECONNRESET）。

   另外，HTML 路线会把底层错误吞掉。所以先做 **P0：模型网关 + 错误分类 + 自动重试 + 回执防重复计费**，再统一混流响度，最后才是新的编排和多模型分层。

## 1. 三条路线定位（附 2026-11-10 实测数据）

| | 创意动画（Lemo） | 模板动画（Remotion） | HTML 动画 |
|---|---|---|---|
| 谁来写画面 | Agent 多轮写整片 JS/Canvas/Three.js 代码 | 固定模板 + AI 生成的图片和文案 | LLM 按场景生成 HTML，套场景模板 |
| 风格 | Lemo 66 种 + OPUSCAR 98，共 164 种 | 已适配 59 种 | 场景模板 |
| 画面怎么出 | 上游 `video.mjs`（Playwright 逐帧） | Remotion 镜头 → 导演渲染器 | 隐藏窗口逐帧截图 |
| 成片怎么混流 | 上游 `mux.sh` 的 TS 移植（−14 LUFS） | 导演渲染器内置混音 | HTML 渲染器内置混音 |
| 实测成片 | 16.1 s，1080p，**−14.0 LUFS / −1.2 dB** | 15.5 s，1080p，−20.7 LUFS | 20.0 s，720p，−20.9 LUFS |
| 实测耗时（4 镜头） | Agent 38 轮约 14 分钟 + 出片约 2 分钟 | 约 17 分钟（含一次 524 重试） | 约 22 分钟（其中素材约 7 分钟，含 5 次配音失败重跑） |
| 付费调用（这一条片） | LLM 40 次、生图 0、配音 6 次 | LLM 1 次、生图 9 次、配音 7 次 | LLM 至少 2 次、生图 11 次、配音至少 6 次 |
| 优势 | 画面独特，风格还原度高 | 稳定、可预期、适合批量 | 图文信息密度高 |
| 风险 | 依赖强模型；轮数多，延迟长 | 画面同质化 | 生图多；错误不透明 |
| 适用 | 品牌片、概念片、风格化解说 | 知识科普、批量解释类 | 资讯、图文解说 |

> 付费调用的计数口径见实跑记录。对结果未知的请求做重试，可能被重复计费，这正是 P0 要解决的问题。

## 2. 各路线技术链路

### 2.1 创意动画（Lemo，authoringVersion 3）

```
文案 → 配音（逐镜头 TTS）→ 时间轴拟合
     → 上游 Agent 循环（electron/lemo-upstream-agent.ts）
          每轮只执行一个工具动作（读/写文件、检查），轮次 journal 落盘，可逐轮续跑
          产物：STYLE.md / TREATMENT.md / scenes.js / main.js …
     → upstream-ready（整片校验）
     → video.mjs（暂存的上游渲染根目录，sha256 校验；Playwright driver node；24 fps）
     → 导演渲染器合入配音
     → mux.sh 移植（两遍 loudnorm −14 LUFS / TP −1.2，颗粒，x264 crf 19，AAC 256k）
     → verify（ffmpeg 探测 + 抽帧）
```

- **关键约束：**
  - `vendor/lemo-upstream` 锁定在 `f171360`，不修改。
  - Windows 适配全部在上游文件之外，共 8 项，见路线拆分文档 §2.1。
- **续跑：**render 失败后执行 `resume`，Agent 的轮次结果全部复用。今天已实测。

### 2.2 模板动画（Remotion）

```
文案 → plan（LLM：分镜、镜头类型、图片提示词）
     → 生图（每镜头背景 + 主体）→ 抠图 → 配音 → 时间轴
     → animation（套模板）→ compile → Remotion 镜头渲染 → 导演渲染器合成 → verify
```

- 生产 DAG 由 `electron/vox-production-runtime.ts` 执行。节点状态分为 `pending / running / completed / failed / unknown`。`unknown` 必须人工或监督程序决定是否重试。
- 老项目（没有 authoring 字段）统一归入这条路线。

### 2.3 HTML 动画

```
rewrite → planning（LLM）→ assets（生图 + 抠图）→ voice → preview（每场景隐藏窗口）→ render（逐帧截图 + 合成）
```

- 步骤产物带 hash 落盘，`retryTask` 从失败的步骤续跑，今天已实测。
- **已知缺陷：**步骤失败时，底层原因被统一归一成「HTML video *step* step failed.」，见 P0-4。

## 3. 共用底座：现状与缺口

| 层 | 内容 | 现状 | 缺口 |
|---|---|---|---|
| L0 存储与产物 | sql.js 任务表；任务目录产物 | ✅ 路线列 `production_route` + 触发器 + 回填 | 整文档 `result.json` 偏大（单个 100–120 KB × 每节点）；磁盘膨胀 |
| L1 模型网关 | LLM / 生图 / TTS 调用 | ⚠️ 各路线各自调用 | 没有能力档案和自动降级（这次 claude 404 → 只能手动换模型）；网络错误分类不统一；没有回执去重 |
| L2 任务编排 | 生产 DAG / 步骤 runner | ⚠️ 两套：vox DAG、HTML runner | `unknown` 节点没有自动策略；重试预算不统一 |
| L3 数据模型 | 分镜 / 时间线 | ⚠️ 三套文档结构 | VideoSpec 统一（只用于新项目） |
| L4 场景运行时 | seek 协议 / 采集 | ⚠️ 多套垫片 | SceneRuntime 协议（`window.__hf`）+ CaptureHost |
| L5 混流 / 编码 / 闸门 | 响度、编码、校验 | ⚠️ 只有 Lemo 达标 −14 LUFS | 模板和 HTML 是 −21 LUFS：把 mux 移植下沉为共用 Encoder |

## 4. 路线图

每一步都能单独上线，旧项目只读兼容（绞杀者模式）。

### P0 稳定性（最优先）

| 编号 | 内容 | 验收 |
|---|---|---|
| P0-1 | **模型能力档案 + 自动降级**：每个 profile 配一个备选链（例如 `claude-sonnet-5-5 → gemini-3.1-pro-preview`）。遇到 404 `model_not_found` 或 503 `model_unavailable` 自动切换，并写进日志 | 主模型不可用时，Lemo 照样能出片，且切换有记录 |
| P0-2 | **统一错误分类**：网络断开（`ECONNRESET`、TLS、`UND_ERR_*`）、网关错误（502/503/520/522/524）、限流（429）、业务错误（4xx）、本地错误。前三类自动退避重试 | 用本地模拟中转站做故障注入测试，全部覆盖 |
| P0-3 | **回执先于解析，防重复计费**：请求带幂等 key；`unknown` 先查回执，再决定是否重发 | 把今天 TTS / 生图的 unknown 场景回放一遍，不产生二次计费 |
| P0-4 | **HTML runner 保留底层错误**：步骤错误码不变，消息附上原因（主机、错误码） | 配音断线时，界面能看到「与 openspeech… 连接中断（ECONNRESET）」 |
| P0-5 | **TTS 链路加固**：单段并发限制、断线自动重试；配置里可设代理或直连 | 在当前网络下，4 段配音一次跑通的成功率 ≥ 95%（需实测） |

### P1 统一混流与采集

- **P1-1：共用 Encoder。**把 `finalizeLemoUpstreamFilm`（两遍 loudnorm、AAC 256k、crf 19）接到模板和 HTML 的成片后面。
  - 验收：三条路线成片都在 −14 ± 1 LUFS，真峰值 ≤ −1 dB。
- **P1-2：SceneRuntime 协议 + CaptureHost**，替换多套 seek 垫片。
  - 验收：预览与导出逐帧一致，有黄金帧测试守护。
- **P1-3：修复老模板项目预览的 `CSS.registerProperty` 重复注册**：每次预览都用新的 iframe 文档，或者在 shim 里吞掉重复注册。

### P2 编排与数据模型（只用于新项目）

- **P2-1：VideoSpec / Timeline 统一数据模型。**三条路线的分镜都写成同一个结构。
- **P2-2：统一执行器。**场景并行，失败互相隔离，先配音后分镜。`unknown` 由策略自动处理，并有重试预算。
- **P2-3：产物增量存储。**节点结果只存差异或引用，去掉整文档快照。

### P3 模型分层与产品化

- **T1 模板**（任何模型都能用）→ **T2 场景代码**（中等模型，走 HTML / Remotion 适配器）→ **T3 Agent 整片**（强模型，走 Lemo）。根据模型能力档案，自动推荐路线或降级。
- **真实回归集**：每条路线 2–3 个固定题材，人工触发，有预算，每次发版跑一遍并归档成片和响度。今天这一轮就是第一版基线。
- **成本面板**：按项目统计 LLM / 生图 / TTS 的调用次数和估算费用，数据来自 P0-3 的回执账本。

## 5. 验收与质量闸门（所有路线）

| 闸门 | 规则 |
|---|---|
| 时长 | 成片时长与时间轴的差不超过 1 帧（Lemo 已强制：`LEMO_EXPORT_DURATION_MISMATCH`） |
| 编码 | h264 + AAC，分辨率等于画布，fps 固定 24 |
| 响度 | −14 ± 1 LUFS，真峰值 ≤ −1 dB（目前只有 Lemo 达标，P1-1 补齐） |
| 画面 | 首、中、尾三帧抽检，不能有黑帧或缺字体；缺失的资源写进回执 |
| 失败 | 每类失败都有错误码前缀（例如 `LEMO_UPSTREAM_RENDER_*`），不允许悄悄放行 |
| 续跑 | 任一节点失败后都能续跑，已付费的结果不重做 |

## 6. 风险与待决策

1. **默认模型**：`claude-sonnet-5-5` 在当前 key 分组下不可用。需要你决定：
   - 换 key 分组；
   - 或者把默认模型改成 `gemini-3.1-pro-preview`（这次实测可用）。
2. **Lemo 成本与时延**：一条 16 秒的片需要约 40 轮 LLM，耗时约 14 分钟。如果要做批量，应该引导用户用模板动画，或者在 P3 中给 Lemo 设轮数和预算上限。
3. **网络环境**：火山 TTS 和 vllmproxy 的不稳定来自本机代理链路（Clash fake-ip）。产品侧只能靠 P0 的重试和回执兜底；根治需要调整网络或供应商。【未核实其他网络环境下的表现】
4. **HTML 路线改动范围**：按之前的约定，本轮没有改 HTML 动画。P0-4 和 P1-1 需要改它，需要你确认。
