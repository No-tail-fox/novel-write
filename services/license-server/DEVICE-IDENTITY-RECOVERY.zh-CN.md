# 重复设备编号：恢复与发布说明

## 原因与当前边界

旧版 Windows 客户端只对注册表 MachineGuid 做哈希。同一系统镜像保留相同 MachineGuid 时，两台物理电脑会显示相同设备编号。服务器旧逻辑只允许该编号有一个有效绑定；当前凭据不匹配时，激活报 DEVICE_ALREADY_BOUND，验证报 DEVICE_NOT_BOUND。按这个编号整体解绑会释放当前占用该编号的绑定，可能影响另一个客户。截图中“已绑定设备为空”来自当前客户端未取得有效租约，不能据此判断服务器没有绑定。

本次为源码修复。经用户提供的连接信息，只读检查了生产服务状态与指定冲突编号的绑定、审计记录；没有修改生产数据库、解绑线上客户、发布安装包或修改 Windows 标识。正式恢复需要先部署并验证服务端，再分发带本修复的客户端；现有已安装的 1.0.3 不会因为源码修改自动获得修复。

## 操作顺序

1. 停止对冲突的旧编号执行整体解绑、锁定或解锁。记录两位客户、各自授权编号/尾号、设备名称以及当前绑定状态；不要在公开日志记录完整激活码。
2. 两台客户电脑分别读取 SMBIOS System UUID，确认硬件标识不同。只读命令：`Get-CimInstance Win32_ComputerSystemProduct | Select-Object UUID`。无需修改注册表、计算机名或 MAC 地址。
3. 使用既有运维流程备份授权数据库及私有配置；安排短暂维护，停止授权服务并暂停旧版 CLI 操作，同时更新服务端、CLI 使用的代码与管理网站，再启动服务。保持签名密钥、CA、端点和已有授权不变。服务端新增身份别名表和绑定令牌列，不清空数据。旧代码的无列名 INSERT 与新列不兼容，不能让新 CLI 先改数据库、旧服务继续运行；回滚也不能仅换回旧代码，须使用兼容列名的代码或按备份方案恢复数据库。
4. 在隔离测试环境验证 v1 兼容、v2 激活/迁移、旧页面解绑冲突拒绝后，再按正式发布流程构建更高版本客户端。不要直接覆盖同版本安装包绕过更新序号规则。
5. 两台电脑分别更新客户端并联网。新版编号结合 MachineGuid 与硬件 UUID，硬件 UUID 不同时应显示不同编号。
6. 仍保留旧密钥、且服务器旧绑定仍有效的一台可自动迁移：服务器验证同一密钥，转移原设备名额，不重置授权期限。迁移后的客户端须得到新编号的签名租约才保存身份转换。
7. 已被解绑或本地旧凭据丢失的一台，用属于该客户的有效激活码正常激活。若名额已满，从新后台核对并释放**该客户的具体绑定记录**；不要为了试错释放另一位客户的绑定。已到期或停用的旧授权不能自动迁移，需要管理员按实际授权情况处理。
8. 两台均验证成功后，再在隔离验收设备验证“解绑/锁定 A，B 仍可刷新”；不要为了验收擅自锁定真实客户。

## 修复机制与限制

- 新编号固定使用 `SHA256(storydream-device-v2 + 换行 + normalized MachineGuid + 换行 + normalized SMBIOS UUID)`；旧编号仅用于证明同密钥迁移与检查历史锁定。
- 硬件 UUID 缺失、全零、全 F 或探测失败时停止授权初始化，不临时回退旧编号或生成随机机器编号。已有 v2 凭据与硬件不符时也拒绝使用。
- 新协议为 `/v2/license/activate`、`refresh`、`release`，请求路径与两个编号均包含在设备签名中。旧服务器会拒绝新端点，需要先升级服务端。
- 同密钥迁移为原子事务；错误激活码、占用目标、停用/到期授权、锁定及签名失败均不能留下部分迁移。旧编号/密钥的迁移记录持久保存，防止旧客户端重新抢占名额。提交后响应丢失可以用同密钥、同目标重试。
- 本地迁移前保存的旧租约不能授权新编号；新租约验证通过且安全保存后才完成本地迁移。更新序号、防回退哈希、私钥和本地时间保护保留。
- 后台“解绑”携带所选授权 ID 与绑定令牌。激活或重绑会更换令牌；旧页面收到“设备绑定已变化”时须刷新核对，不能扩大为按编号整体解绑。命令行 `release-device` 仍为明确的整编号运维操作，冲突旧编号不得用它恢复单个客户。
- 若旧编号被锁定，新协议也保持拒绝，不能靠升级或删除凭据绕过锁定。锁定本身有身份歧义时，需要管理员核实两位客户后处理。
- 完整克隆虚拟机可能连 SMBIOS UUID 一起复制；这种情况下本修复不能证明两台机器不同，仍需处理虚拟机硬件标识或采用另行设计的设备恢复机制。只靠计算机名不同不能解决问题。
- 旧客户端兼容期间，旧程序仍不具备硬件身份能力；服务器不提供硬件远程证明，也不能防止篡改程序。已发出的有效离线租约只能在客户端收到拒绝或签名期限结束后失效，不承诺即时远程失效。

## 本地验证

回归测试覆盖：相同 MachineGuid/不同 UUID 的隔离、规范化和无效硬件值拒绝、旧凭据迁移与离线限制、签名不正确/旧服务端/响应丢失、真实 TLS 双设备激活/迁移/锁定/解绑、名额与到期时间保持、迁移并发和事务回滚、后台陈旧绑定令牌拒绝。验证只使用临时测试数据库与本地 TLS 服务；不能替代客户机器及生产部署验收。

本次结果：101 项客户端/授权/更新/IPC 测试通过，30 项服务端及后台测试通过，Electron TypeScript 检查与所改 TypeScript 的 ESLint 检查通过。后台交互在 1440×900 与 1000×720 两种窗口下通过取消、陈旧绑定拒绝、刷新令牌与正确解绑验证。开发机 Windows 硬件读取成功，仅记录格式是否正确，不输出原始硬件标识。
